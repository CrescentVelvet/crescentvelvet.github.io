## 洛克茜像素画 → 半格 ANSI（一次性资源任务，产物不进仓库）

目标：把用户自绘的洛克茜像素立绘转成与 `克拉蕾_彩色ANSI字符画.txt` 同款格式（半格 ▀、真彩）。

**输入参考格式**：110 列 × 55 行，每格 `ESC[38;2;R;G;Bm ESC[48;2;R;G;Bm ▀`，行尾 `ESC[0mESC[0m`，LF 换行。fov=上像素、bg=下像素 ⇒ 等效 110×110 像素画。调色板 k-means 实测仅 4 族：暖黑 `#110B0D`、血 6 阶、金 5 阶、暖灰米白 7 阶。

**用户作品**：1254×1254 JPEG（原生栅格 ≈130×130，块宽 9.65px，9/10 交替；FFT 周期 + 边缘间距直方图双确认）。19 色。

**结论/坑**
- 直接降采样原图 = 掉档（黑衣服吃掉结构线）；风格化必须**重新绘制**（ImageGen img2img，image1=角色、image2=风格参考，prompt 要写死"3.2 头身 / 每件衣服一整块黑 + 1px 亮勾边 / 删掉铆钉皮带"），再量化。
- 量化时**金色判定必须加高饱和门槛**（s≥0.45），否则肤色/米白被误染成金块。
- 色阶数量要压到 2–3 阶/材质，长 ramp + 抖动在平涂面会产生满屏噪点。
- 抠底遮罩注意别写反（`bg_mask` 与 `fg` 混用会把人物整块刷成背景色，曾把双腿刷没）。
- 已有像素画要回缩时，**优先整数裁剪而非重采样**：130 图裁 110 窗口（crop 12,20,122,130）人物仍 76px，与女王 78px 同级且零模糊；重采样到 110 会让人物掉到 64px 且白描边碎成噪点。

**产物**：`Downloads/洛克茜_彩色ANSI字符画.txt`（130×65，258,585 B）、`洛克茜_彩色ANSI字符画_110x55.txt`（110×55，188,895 B）。两者编码→渲染回图 `max diff = 0`。临时脚本在 `.workbuddy/tmp/roxy_ansi/`（style3.py 量化器、ansi_encode.py、retro.py 调色板重建），未入库。

## 洛克茜立绘换新（110×55 ANSI）+ 发丝/武器微动

用户要求把 `link_up` 里的女仆形象换成刚产出的 110×55 版，并提出"发丝与武器微动"。

**做成分层立绘**：`tools/ascii_mv/build_roxy_actor.py` 在 import 产物上再生成 `parts`
字段（每格一个字符，`0` body / `1` hair / `2` weapon），渲染端 `luRoxyLayers` 出 3 张
canvas，`luRenderRoxy` 分别绕锚点旋转。

**分层的三个要点**
1. `parts` 必须**互斥**：入场 `reveal<1` 时，两层同时 claim 同一格会显成双影。
2. 层要**向外多吃 1 格**（8 邻域膨胀）。旋转 4° 后层与主体间会张开 1~2 源像素的缝，
   透出背景，读成"头发被撕开"。膨胀吃的像素还是它自己的颜色，静止时与主体完全重合。
3. 锚点放**根部**（发束根部 x0.565/y0.245、锤子握把 x0.70/y0.565），缝隙在锚点处为 0。

**锤子 mask 不能只按颜色取**：宝石/内腔与钢板不连通，纯颜色测试会留下不动的洞；
做法是 钢∪高光∪亮红宝石 → 1px 闭运算 → floodfill 填洞 → 膨胀 1 吃黑描边，
最后只保留 钢/高光/宝石/黑描边 四类，暗红裙摆（17–19）不进 mask。

**幅度按屏幕像素定，不按物理**：s13 里她 26 格宽，一源像素 ≈1.7 屏幕 px，
2° 在发尖只有 1.2px，逐帧 diff 都看不出在动。现在发丝 4.4°+横向 3 源像素（≈4px 位移）、
大锤 2.3°+竖向 2 源像素，24fps 下才是"飘"而不是"抖"。

**⚠️ 身高配平踩的坑（最重要）**：我按"女王 84×140"算净高，得出洛克茜要 ×1.45 宽，
结果她反而比女王高 32%。实测数据后才发现 **两张图现在都是 110×110**（84×140 是更早那版，
早被替换了）：
```
queen  w110 h110 content y2..105  ratio 0.945
roxy   w110 h110 content y9..102  ratio 0.855
```
显示高度都 = 宽/2，只差内容占比 ⇒ **配平系数 = 0.945/0.855 ≈ 1.105**。
改完后实测截图：女王 202px / 洛克茜 208px（差 3%，多出来的是发束飘高），脚底同为 424px。
教训：涉及"两个素材对齐"时，先 `node -e` 读真实 width/height/content 范围，别信注释里的旧数字。

**其它定案**：新图底部自带一条虚线红色地平线（y≥98，x 10..100 远离脚），导入时按
`x<40 或 x>77` 清掉（脚底的保留，读成地面反光）；`import_ansi_actor.py` 的低色数图
调色板只返回实际用到的颜色，`range(0,66,3)` 会切出空 tuple → 改按 `len(rawpal)//3`。

**尺寸（全部按 1.105 配平）**：s10 单人 50 格宽（25 行，不再裁腿）；s12_duo 32/36；
s12_shatter 女王 70 / 洛克茜 100（按脸占比，Q 版脸小要更大的图）；s13 19/21；s14 20/22。

验证：`ROYAL CHECKS 360`、errors=0；`link_up_roxy_duo2.gif`（162 帧 / 近重复 0）、
`link_up_roxy_dream2.gif`（150 帧 / 近重复 0）。

## 双人镜头改按"脸"配平（女王 vs 洛克茜）

用户反馈：女王手持大镰刀更压场，女仆应该比女王矮一点，但**要用"脸一样大"来定缩放**，
不要单纯比身高。上一版按"内容高度占比 0.945/0.855"给她 ×1.105 宽，等于把她的脸放大 10%，
这才是"并排看着不协调"的真因。

**量脸的方法（可复用）**：源图都是 110×110，直接比**两眼红块中心距**最稳：
```
queen  左(56,38)  右(64.5,40.5) → 8.86 px
roxy   左(48.5,38) 右(57,36.5)  → 8.63 px
```
差 2.6% ⇒ 同宽时脸几乎等大。换到"眼到下巴"也是 5.5 px vs 5.5 px，结论一致。
（试过按肤色连通块/发色包围盒量，都被长发和大发量污染，不可用。）

**但"脸等大"≠"人等高"**：她的发量比女王蓬，头顶在源图 y≈9（女王 y≈20，还戴皇冠），
按脸配平后她的头顶反而高 6px。所以 `luRoxyW()` 里再加 `LU_ROXY_SHRINK = 0.92`：
脸小 8%（30px 的脸差 2px，肉眼无感），头顶低 6px，回到"女王略高、女仆略矮"。
⚠️ 别压到 0.85 以下——脸明显小一圈会读成"姐姐带妹妹"，和"并立双人"不是一回事。

四处调用点（`luRoxyW`）：s12_duo 32 / s12_shatter 70 / s13_throne 19 / s14_pull 20；
s12_shatter 原来给她 100 格宽（脸比女王大 47%，快切就忽大忽小），现在两人同一推镜倍率。

**新增工具** `tools/ascii_mv/render_sprite.py`：把导出的立绘 .js 渲染成带坐标网格的 PNG
（`--crop x0,y0,x1,y1` / `--tint i,j` 压暗非目标色），量脸、量锚点、确认某个色是不是脸都靠它。
⚠️ 网格必须在 **crop 之后**画，否则坐标标签被裁掉；`grid` 线要按源像素坐标取整。

验证：`ROYAL CHECKS 360`、errors=0；`link_up_scale_a.gif`（162 帧）、`link_up_scale_b.gif`
（244 帧），近重复均 0。

## 发束分层重做 + 女仆再缩 5%（用户第三轮反馈）

用户两条：① 女仆再缩小 5%；② 头顶"飘起来的三根头发"在飘，但**整块头发**跟着一起摆，很怪。

**根因**：`build_roxy_actor.py` 原来用矩形 `HAIR_BOX=(40,0,78,27)` 把头顶框内**所有**不透明
像素都算成 hair 层 —— 实际取到的是 18×27 的一块实心板（含整个发团和头骨顶部）。绕一点旋转
4.4° 后整个人像"后脑勺在晃"。渲成掩膜图一看就明白（`.workbuddy/tmp/roxy_head_parts.png`）。

**改法**：手描三条**逐行 x 区间**（`STRANDS` 字典），只取真正伸出发团的三束：
```
左鬓   tip(46,15)  y15-18  x44..49   根(46.5,18.5)
顶发   tip(60,9)   y9-12   x57..64   根(60.0,12.5)
右甩   tip(70,17)  y12-18  x64..71   根(64.5,13.5)
```
parts 重编号 **0 body / 1 左 / 2 顶 / 3 右 / 4 weapon**（原 0/1/2）；`luRoxyLayers` 循环到 5 层。
⚠️ 换层号必须同时改 `LU_ROXY_LAYERS`、`LU_ROXY_HAIR`、武器 `part(4,…)` 三处。

**位移用"旋转 + 剪切"双通道，锚点都在根部**：
- `rotate(angle)` 绕根转，根不动；
- `transform(1,0,-shear,1,0,0)` 越往上弯得越多（鞭状）；canvas y 向下、发尖在 y<0，
  所以矩阵里取负号才和正角度同向。
- ⚠️ **不要用纯平移**：平移会把根从发团里拔出来，即使 1 格膨胀补缝也会看到断口。
- 幅度：三束 ang 0.14/0.16/0.10 rad + shear 0.34/0.40/0.20，根→尖 3.5/3.5/6.5 源像素
  ⇒ 发尖位移 ≈ 2.0 源像素。s12_duo（29 格）≈ 4 屏幕 px、s13_throne（17 格）≈ 2.2 屏幕 px @864。

**尺寸**：`LU_ROXY_SHRINK` 0.92 → **0.874**（= ×0.95，用户要的 5%）。864px 画面里她的
发顶现在比女王低 10px（改前 5px）。仍守住"不低于 0.85"的底线。
`s10_dreamt` 的单人镜头用的是固定 50 格（不走 `luRoxyW`），不受影响、也不该受影响。

验证：`ROYAL CHECKS 360`、errors=0；`link_up_roxy_hair.gif`（98 帧 / 4.08s / 3.8MB）、
`link_up_roxy_throne_hair.gif`（99 帧 / 4.12s / 1.3MB），近重复均 0。
⚠️ `encode_royal_gif.py` 的接触表时间点是**写死**的（80~95.8s），换段时间要省掉第三个参数。

   玻璃球连栽两版（先成金环、再成粉白圆环），正解是球面法线 `sh = ux*Lx+uy*Ly+nz*Lz`。

5. **血滴的主体不能是黄**：`nn>0.6 → █B` 会让整颗滴成"上黄下红的火苗"。橙只做

6. **地面拆成"横线+竖线"画 = 一堆虚线**：`hash` 概率打断的横线在 864px 下读不成地面。

7. **崖壁逐根立柱 = 管风琴**：柱间距 1.4 格时加宽也没用。正解是**沿 x 的高度函数**

8. **崖壁纹理不能用 `hash16(x*53 + y*191)`**：逐列独立随机 ⇒ 相邻列图案无关 ⇒
