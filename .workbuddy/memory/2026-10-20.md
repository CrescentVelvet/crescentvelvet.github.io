## 高斯对比：逆光泛白「焊死在衣服上」根因（SH degree=0）

峰哥报：逆光重建模型在 SuperSplat 里泛白随视角变化，本页泛白固定贴在衣服上。
- 根因：3DGS 的视角相关颜色由球谐(SH)编码；页面构造写死 `sphericalHarmonicsDegree: 0`，
  只保留 DC 平均色 ⇒ 逆光泛白被平均进基础色、转角度不再变化。SuperSplat 用完整 SH 故正常。
- 库限制：着色器只实现 degree 1/2 采样分支（vendor L7715/L7740 只有 `=== 1` / `=== 2`），
  degree 3 会走未初始化分支；45 个 f_rest 最多上传前 24 个 ⇒ 安全上限 degree 2。
- 代价实测（real.ply 116 万 splat，正反序各测一次排除冷缓存）：ready 4.4s → 6.0s（+1.6s），
  显存/带宽 ≈ +48MB/百万 splat（Uint16 半精度）。PLY 解析本身不变（始终读全部 SH）。
- 验证：tmp/sh_ab.js（SH2 vs SH0 同机位 A/B）像素差异 3.59%/2.38%/1.54%、maxAbsDiff 76/55/43，
  renderCount 全量、无页面错误 ⇒ SH 确实进了着色器。回归 26/26 + 静态全过。
- 说明：real.ply 非逆光模型，差异偏小；峰哥的逆光模型应显著。

## 高斯对比：渲染设置对齐 SuperSplat（参数级，峰哥要求）

对照源（GitHub playcanvas/supersplat 默认值）：`src/scene-config.ts` 的 DEFAULT_BG_CLR /
camera.toneMapping / camera.fov / show.shBands，`src/main.ts` 的 createGraphicsDevice，
`src/scene.ts` 的 devicePixelContentBoxSize 与 pixelScale 语义。

已改（`_pages/splat-compare.html`）：
- renderer 构造加 `depth:false, stencil:false`，保留 `antialias:false` + `powerPreference`（对齐 graphicsDevice）。
- 显式 `toneMapping = NoToneMapping` + `toneMappingExposure = 1`（SuperSplat `toneMapping:'linear'`、`exposure:1.0`）。
- `fov 65 → 85`（SuperSplat 默认），`far 500 → 1000`（PlayCanvas CameraComponent farClip 默认）。
- `halfPrecisionCovariancesOnGPU: true → false`（PlayCanvas 协方差是 f32；实测无视觉差异，代价约 12B/splat）。
- `setPixelRatio(1) → window.devicePixelRatio`（SuperSplat 按 devicePixelContentBoxSize 物理像素渲染）。
  峰哥拍板「一致性优先」，代价是 HiDPI 屏片元 ×4。

故意不一致（峰哥拍板）：
- 背景色保留 `#222233`，不跟 SuperSplat 默认纯黑 —— 纯黑会把模型暗部糊进背景。

无法一致（库/引擎硬限，需告知）：
- SH bands：SuperSplat 默认 3（45 系数），本库着色器只有 degree 1/2 分支 ⇒ 上限 2（24 系数）。
- 渲染后端：SuperSplat 优先 WebGPU，本页 three + gaussian-splats-3d 走 WebGL2。
- 无 stochastic sorting（SuperSplat `view.stochastic:'auto'`，移动时抑制排序 pop）。
- GPU radix sort 不可用（库 bug 会黑屏，见 MEMORY 的 gpuAcceleratedSort:false）。

回归：`unify_semantics.js` 26/26 PASS、`check_splat_compare.js` 全过、
新增 `tmp/verify_render_parity.js` 10/10（context depth/stencil/antialias=false、canvas 宽/CSS 宽 === dpr、
fov=85、nonBg 9.3% 画面有内容、页面零异常；截图 `tmp/parity_fov85.png`）。
