## 高斯对比：逆光泛白「焊死在衣服上」根因（SH degree=0）

峰哥报：逆光重建模型在 SuperSplat 里泛白随视角变化，本页泛白固定贴在衣服上。
- 根因：3DGS 的视角相关颜色由球谐(SH)编码；页面构造写死 `sphericalHarmonicsDegree: 0`，
  只保留 DC 平均色 ⇒ 逆光泛白被平均进基础色、转角度不再变化。SuperSplat 用完整 SH 故正常。
- 库限制：着色器只实现 degree 1/2 采样分支（vendor L7715/L7740 只有 `=== 1` / `=== 2`），
  degree 3 会走未初始化分支；45 个 f_rest 最多上传前 24 个 ⇒ 安全上限 degree 2。
- 代价实测（real.ply 116 万 splat，正反序各测一次排除冷缓存）：ready 4.4s → 6.0s（+1.6s），
  显存/带宽 ≈ +48MB/百万 splat（Uint16 半精度）。PLY 解析本身不变（始终读全部 SH）。
- 验证：tmp/sh_ab.js（SH2 vs SH0 同机位 A/B）像素差异 3.59%/2.38%/1.54%、maxAbsDiff 76/55/43，
  renderCount 全量、无页面错误 ⇒ SH 确实进了着色器。回归 26/26 + 静态全过。
- 说明：real.ply 非逆光模型，差异偏小；峰哥的逆光模型应显著。

## 高斯对比：Stochastic Alpha 与 SH bands 3 的核查（回答峰哥）

### 1) SuperSplat「Stochastic Alpha」——本页不需要改
- 语义（SuperSplat 3.0 release notes + settings-panel.ts）：无排序随机透明，把 splat 当
  不透明片元做深度测试 + 逐片元随机覆盖率采样；仅移动时用，静止后补一帧完整排序。
  选项 Disabled / Enabled / Movement / Auto（默认 Auto）。颗粒感就是随机覆盖率的噪点。
- 本库 grep `stochastic|dither|randomAlpha|alphaHash|hash(|noise` **零命中** ⇒ 根本没有该机制，
  永远走「排序 + alpha 混合」，等价 SuperSplat 的 Disabled。**无需任何改动**。
- 推论：本页若出现颗粒感，来源不可能是随机 alpha（只能是 dpr 不足 / 排序错误 / 模型本身稀疏）。

### 2) SH bands 3——是本库 shader 硬缺失，不是权衡
- 证据：`buildVertexShaderSH` 只有 `=== 1`（L7715）、`else if (=== 2)`（L7740）、
  二级采样 `=== 2`（L7796）三个分支；而 L7778/L7830 **无条件**读 sh1..sh8 累加。
  degree 3 时三个采样分支全不命中 ⇒ sh1..sh8 未初始化（GLSL UB），
  实测表现可能是颜色退化成只剩 DC（= 逆光泛白焊死复发）或花屏。
- 数据层其实装得下：L253-254 degree 3 → 45 系数，L10065-10066 按 minDegree 分配数组。
  即「传得进、读不出」。
- 实测代价（real.ply 119.9 万 splat，脚本 `tmp/sh_band_energy.js` / `tmp/sh_deg23_delta.js`）：
  - 各阶占 SH 总能量：band1 15.11% / band2 30.20% / **band3 54.68%**；
    每系数 RMS 0.0607 / 0.0665 / 0.0756（逐阶递增，说明 PLY 的 channel-major 布局解析正确）。
  - 球面 68 个方向 × 5.99 万 splat：degree2 vs degree3 的 RGB 差
    **RMS 0.0968（≈9.7% 动态范围，14.3/255 每通道）**，中位数 0.0406，p90 0.1455，p99 0.3521，max 1.0859。
  - ⚠️ **修正上一轮的说法**：band3 不是「可忽略的高频细节」，它占 SH 能量一半以上，
    色差量级可见。degree 2 相比 SuperSplat 确实有实质损失。
- 若真要支持 degree 3：必须改 vendor 的 SH 采样/packing（7 个基函数 + texel stride 6→12 +
  multiTextureMode/8bit 两种打包都要覆盖），属改第三方库，升级即丢；需峰哥拍板。
