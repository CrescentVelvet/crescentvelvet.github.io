## 高斯对比：平移改为「屏幕像素意图」广播（第十轮）
- 用户报：单独调整后，查看模式右键拖平移，多模型"平移不一致"。
- 根因：右键平移在 OrbitControls 里是**屏幕空间**操作 ——
  `Δt_world = right·(−2·dx·td/H) + up·(2·dy·td/H)`，`td = dist·tan(fov/2)`。
  原先广播的是**世界位移**，各面板经单独调整后朝向（dAz/dEl）、距离（distRatio）不同，
  同一世界向量在各自屏幕上的投影方向/幅度都不同 ⇒ 必然走偏。
  （左键旋转、滚轮缩放**不受影响**：角度增量与比例增量与相机局部坐标系无关，天然一致。）
- 方案：广播「像素意图」。(dx,dy) 由源面板世界位移反算，接收面板按**自身相机**换回世界位移，
  并演化自身私有 `dTarget`：`dTarget_new = st_p.target + dOwn − base_new.target`（绝对值，不累加 ⇒ 不漂移）。
- 实现：新增 `panScale` / `worldToPanPixels` / `panPixelsToWorld`（三处共 26 行）；
  `broadcastCameraState` 加 `isPan` 分支（判据：target 动了而 az/el/dist 未动）；
  新增调试钩子 `window.__project(x,y,z)`（世界点 → 各面板屏幕像素）+ `window.__lastBroadcast` 诊断。
- 验证：
  - 新 `tmp/pan_sync.js`（两模型真实 CDP 右键拖）**8/8**：P3 屏幕位移差 0.00px；
    P4 单独调整中平移仍隔离；P5 第二次平移仍 0.00px（增量不漂移）。
  - 旧 `tmp/unify_semantics.js` **26/26**：T7 断言已从"世界 target 增量相同"改为
    "世界点屏幕位移一致"（旧断言编码的正是本次要修的 bug）。
  - `tmp/check_splat_compare.js` **51 项全通过**（新增 3b 节 6 项守卫：三函数存在 +
    isPan 分支 + 接收面板换算 + panScale 与 OrbitControls 参数一致）。
