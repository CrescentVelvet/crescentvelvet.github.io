## 高斯对比：平移改为「屏幕像素意图」广播（第十轮）
- 用户报：单独调整后，查看模式右键拖平移，多模型"平移不一致"。
- 根因：右键平移在 OrbitControls 里是**屏幕空间**操作 ——
  `Δt_world = right·(−2·dx·td/H) + up·(2·dy·td/H)`，`td = dist·tan(fov/2)`。
  原先广播的是**世界位移**，各面板经单独调整后朝向（dAz/dEl）、距离（distRatio）不同，
  同一世界向量在各自屏幕上的投影方向/幅度都不同 ⇒ 必然走偏。
  （左键旋转、滚轮缩放**不受影响**：角度增量与比例增量与相机局部坐标系无关，天然一致。）
- 方案：广播「像素意图」。(dx,dy) 由源面板世界位移反算，接收面板按**自身相机**换回世界位移，
  并演化自身私有 `dTarget`：`dTarget_new = st_p.target + dOwn − base_new.target`（绝对值，不累加 ⇒ 不漂移）。
- 实现：新增 `panScale` / `worldToPanPixels` / `panPixelsToWorld`（三处共 26 行）；
  `broadcastCameraState` 加 `isPan` 分支（判据：target 动了而 az/el/dist 未动）；
  新增调试钩子 `window.__project(x,y,z)`（世界点 → 各面板屏幕像素）+ `window.__lastBroadcast` 诊断。
- 验证：
  - 新 `tmp/pan_sync.js`（两模型真实 CDP 右键拖）**8/8**：P3 屏幕位移差 0.00px；
    P4 单独调整中平移仍隔离；P5 第二次平移仍 0.00px（增量不漂移）。
  - 旧 `tmp/unify_semantics.js` **26/26**：T7 断言已从"世界 target 增量相同"改为
    "世界点屏幕位移一致"（旧断言编码的正是本次要修的 bug）。
  - `tmp/check_splat_compare.js` **51 项全通过**（新增 3b 节 6 项守卫：三函数存在 +
    isPan 分支 + 接收面板换算 + panScale 与 OrbitControls 参数一致）。
- ⚠️ 教训（测量方法）：跨 CDP 调用读"投影 + 相机状态"会读到**不同帧**（damping 未收敛），
  曾误报 118px 漂移。测量前必须 `settle()` 轮询到 `__debugCameras()` 连续两次相同再读。

## 高斯对比：单面板「上下翻转」（第十一轮）
- 用户问："加一个单独上下翻转按键、删掉整体上下翻转，还是怎么做比较好"。

  （4 个面板全颠倒要点 4 次）；而翻转性质上不是相机而是**模型**状态，与「单独调整（相机）」不同维，
  所以是把 `allFlipped: bool` 升级成 `panel.flipped: bool` + 一个批量动作，而不是"复制一个按钮"。

  `forceResort` + `syncFlipButton`）；`setAllFlipped(on)` = 对所有面板置同一状态；`allPanelsFlipped()`
  驱动顶部按钮 active（混态 = 不 active，点一次全翻过来）。角标 `.panel-canvas-wrap.flipped::after` 标"上下翻转"。
  换模型/关面板清 flipped；新增钩子 `window.__flip`。
- 验证：新 `tmp/flip_panel.js`（2 模型 + 真实点击 DOM）**17/17**：面板0 翻后 quat=[1,0,0,0]、

  角标/按钮状态；全翻→复位→混态一键全翻均正确。
  ⚠️ E2E 抓到真 bug：单面板翻转没同步顶部按钮（显示滞后），已在 `setPanelFlipped` 内补 `syncFlipButton()`。

## 高斯对比：平移分量无条件走像素意图（第十二轮）
- 用户提议：把判据改成"平移分量永远走像素意图"。**同意** —— isPan 判据本质是在猜
  "这一帧是不是纯平移"，混合帧（旋转阻尼余波 + 平移同帧）必然猜错并静默退化回世界向量广播。
- 改法：判据整个删除。`dWorld = base.target − prev.target`；`dWorld` 非零就走像素意图，
  为零（纯旋转/缩放）时天然跳过 ⇒ 与原路径等价。
- ⚠️ **同时发现并修掉一个真 bug**：混合帧里，"世界 → 像素"的还原用的是**旋转之后**的实时基，
  导致像素意图被同帧旋转额外拧一下。实测（原子注入 18° 同帧旋转 + 90/50px 平移）：
  接收面板偏 **6.7°**；改用**源面板变化前的基**（每面板缓存 `panBasis`，广播末尾刷新）后
  误差降到 **6e-4**（已在探针 3 位小数量化精度内）。纯平移时基不变，所以此前测不出来。
- ⚠️ **方法论教训（第二次踩）**：先用真实鼠标构造"旋转余波 + 平移同帧"，用"整段累积世界位移 ÷ 变化前基"
  当 oracle —— **错**。基在整段序列里持续转动，每帧像素意图是在**当帧**基里解释的，
  拿变化前的基换算整段累积值必然误报（曾报 18.42px 假失败）。
  正确做法：**原子注入单帧混合变化**（新增钩子 `window.__mixChange`），基在该帧内不变 ⇒ 期望值可精确计算。
  判据：**别用"猜不稳的时序"去测"必须在同一帧里才成立的性质"**。
- 探针补充：`__debugCameras` 增加 `fov` / `panBasis`（右/上轴 + 世界单位每像素 + clientHeight），
  供回归脚本核对自算的基（诊断出"基一致 ⇒ 问题不在基"）。
- 验证：`pan_sync.js` **12/12**（新增 P6 混合帧：两面板各自回算像素意图误差 <1e-3、同帧旋转同步）、
  `unify_semantics.js` 26/26、`flip_panel.js` 17/17、`check_splat_compare.js` 全通过（3b 节新增"必须用 panBasis"守卫）。
- commit：`88c7906 高斯对比: 平移分量无条件走像素意图，并用变化前的基还原`（未 push）。
