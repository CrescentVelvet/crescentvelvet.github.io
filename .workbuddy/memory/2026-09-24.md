### 修正后的物理模型

```
X = 左右（主推进/卷轴轴）
Z = 纵深（走位 · 躲避 · 前后包夹）
Y = 跳跃高度（独立轴，仅用于躲地面 AoE 与空中攻击）
无平台、无梯子；危险物 = 尖刺坑（眩晕）+ 移动尖刺
```

代价：① 攻击判定变**两轴对齐**（|Δz| < 阈值 才命中 —— 这才是清版动作「打空」的来源，也是其手感精髓）；
② 渲染需 **z 深度排序**（屏幕 y = 基线 + z 映射）；③ 敌人 AI 要会用 z 轴包夹。
红利：纵深走位**不增加美术量** —— 角色只做左右两套朝向（镜像），z 移动只改屏幕 y。

规格既定，当日落地实现。**产出 `_pages/dual_blade.html`（1437 行内联 JS，零位图，单文件）**。

### 结构与关键定案

- front matter 用 **`layout: null`** —— 本站三个游戏页（tower_defense / sandbox_war_game /
  game_plane）都是这个写法。好处：整页自己接管，顺带**绕开**「`#site-nav` 缺席 ⇒ main.min.js
  greedy-nav 每次加载必栈溢出」那个坑（`layout: null` 根本不加载站点 JS）。
- 三轴：X 左右 / Z 纵深（0~46，`zScale 5.4`，屏幕 y = `baseY + z*zScale`）/ Y 高度。
  **z 深度排序渲染**（z 小的先画）；`DEPTH_SCALE(z) = 1 + z*0.0032` 只做极轻微透视。
- 两轴判定 `canHit()`：`|Δz| >= 15` 必打空（开区间）；高度轴**非对称** —— `t.h - a.h > 26` 打空
  （于是「跳起来躲」成立）、`a.h - t.h <= 62` 可中（跳劈）。这条非对称是整套手感的核心。
- 内容**数据驱动**：`WEAPONS` / `ENEMIES` 定义表 + 行为标签组合（战锤 `onHit:[{stun},{knockback:'toEdge'}]`）。
  加了 `comboReach`（剑第二段略远）。**断言 #11 直接验证「加一条数据即生效、逻辑一行未改」**。
- 角斗士 `guardFront`：`sign(攻击者.x − 目标.x) === 目标.facing` 判格挡。
  ⚠️ **正负号写反就会变成「背面无敌」**，且肉眼很难看出来 ⇒ 已固化为断言 #6（正面 0 伤害 / 背后扣血）。
- 击退分两种：普通位移型（0.5 倍身高）与战锤 `toEdge`（打飞到屏边）。
  ⚠️ **击退必须放在 `physics()` 的死亡判定之前** —— 否则一击致死的目标会跳过飞行，
  「打飞到屏边」既看不见、断言也永远取不到值（第一版就是栽在这里）。
- 单人有预留：`players` 是数组 + `INPUT_MAPS[0/1]`，`__dbg` 断言 #12 守这条。

### 本轮踩到的坑（都已回写进 `cdp-browser-e2e` skill）

1. **探针必须静音关卡波次**：`goto(x)` 传送玩家会把所有 `at <= x` 的波次一次性触发 ⇒
   刷出的小兵推挤玩家 → 相机漂移 → **击退终点断言不再确定**。查了两轮才定位。已加 `silenceWaves()`。
2. **别用 `execFileSync(process.execPath)` 做语法校验**：Windows 上随机 `EBUSY`（父进程就是同一个
   exe），会报出根本不存在的语法错误。改用进程内 `new vm.Script()`。
3. **深度投影下的「区域」必须查宽高比**：尖刺坑 z 带 24 单位 → 130px 高，而 x 只有 110px
   ⇒ 比宽还高，渲染出来读成「一扇黑门」。**所有坐标断言都是过的**，只有看图才发现。
   另：尖刺基座贴**远**边时尖顶会冒出远边之外，读成「平台上插了一排栅栏」⇒ 改成基座贴近边。
4. **教学提示必须限定窗口**：只判 `p.x > x0 - 190` 会永远成立，之后任何时刻都会被这条过期提示
   顶掉新提示（实测盖掉了角斗士的教学）。
5. 探针里凡涉及距离/帧数，**从几何算，别写死** —— 坑的 x0/x1 一改，写死的帧数会静默失效。

**另一个探针设计教训（已回写 skill）：**
输入策略用「一直按住 attack」时，边沿触发只会挥出**第一刀**，之后永不再攻击
⇒ 击倒恒为 0、玩家被围殴致死，**读起来像「卡死/掉帧」，其实是判负**。
纯数字探针的「异常」要先怀疑探针自己的输入模型，再怀疑被测代码。
