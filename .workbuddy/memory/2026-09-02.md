## 沙盘战争：士兵单位视觉改版（设计讨论，未实现）

目标文件：`_pages/sandbox_war_game.html`

### 问题诊断
士兵在坦克旁显"突兀"的根因不是画得丑，而是**信息量不对等**：
- 基础 `Soldier`（type `'soldier'`）是全场**唯一配件数为 0** 的单位（只有 head + body）。
  对比：坦克 6 件、骑兵 6 件、近战/弓/弩/火枪/掷弹各 2 件、工兵/医疗/反坦克各 1 件。
- `.soldier-head` 是 9×8，但 `.soldier-body` 从 y=6 起覆盖，**实际只剩 9×5 的薄片**。
- `.soldier-shadow` 是 14×6 硬边矩形（.38），跟车辆的 `.vehicle-shadow` 椭圆（.30）并列很跳。

### 关键尺寸事实（易踩坑）
- 单位用 DOM + CSS 画，非 canvas。`.unit` 尺寸 = `--unit-size`，内部 `.unit-body` = `--body-size`，
  再 `scale(var(--scale))`。士兵：unit 14 / body 22 / scale 0.636。
- 因此 **1 个 `.unit-body` CSS 单位 ≈ 0.64 屏幕像素**。屏幕可辨识下限约 2px ≈ **3 个容器单位**。
  现有武器（.firearm-gun / .antitank-tube / .engineer-tool）都是宽 3px，即约 1.9 屏幕 px。
- `.unit` 与 `.unit-body` 均无 `overflow:hidden`，所以配件可以伸出包围盒（坦克炮管 top:-5px 已验证）。
- 士兵可见区约 **9×14px**，只有坦克（约 20×23px）的 45% 宽。像素预算上限：
  **1 个轮廓 + 2 级明暗 + 1 个破形元素**。

### 已确认的设计决策（峰哥选定）
- **A1 同语言化**：复用坦克的形体语法，不做符号化、不做具象小人。
- **B3 斜切方块头**：保留方块但切上两角，呼应倒角车体。
- **C1 暗躯干**：躯干 `--color-dark` / 内芯 `--color` / 头盔高光 `--color-light`，
  与坦克 暗车体/主色/亮炮塔 一一对应。（士兵整体会变暗，队伍色块没现在跳，已接受）
- **D1 竖直步枪**：右肩通道（现有武器统一 left:14px），宽 3 单位，向上破形约 4.4px，
  与坦克炮管同源，随 `--angle` 旋转指示朝向。
- **接地投影改椭圆**：rx6.6/ry2.2，透明度 .38→.30，与 `.vehicle-shadow` 一致。
- **改动范围：只改步兵基类** `.soldier-body` / `.soldier-head`，影响基础士兵 +
  engineer/medic/antitank/melee/archer/crossbow/firearm/grenadier 共 8 个兵种。
  骑兵（.cavalry-*）本轮不动。

### 实现时必须处理
1. 现有 per-unit 规则直接设 `background`，会盖掉 C1 的暗躯干（如 708 行
   `.unit.archer .soldier-body{background:#567a57}`、692 行 `.unit.melee .soldier-head`）。
   → 躯干改成**外壳 + 内芯 + 高光**三层，用 `--soldier-hull / --soldier-core / --soldier-hi`
   变量驱动；per-unit 规则只改 `--soldier-core`。
2. 头部几何：切角多边形 y 0.6..7.8（宽 6.2..15.2）；躯干顶边 y=7.4（宽 7.64..14.36），
   因此头部左右各外探约 1.4 单位，横向破形成立。躯干需下移/收高，避免再压掉头部。
3. 步枪 x 15.2..18.2 / y 0.5..10.5，与头部右边缘 15.2 相邻不重叠。

### 实现结果（commit 438e22a）
实际落地与上面的规格有微调，记下来以免下次改错：
- 躯干 `left:5 top:7.4 w:12 h:12.6`，八边形 clip-path；`background: var(--soldier-hull, --color-dark)`
  + `inset 0 0 0 2px var(--soldier-core, --color)`（主色描边环，占躯干面积约 54%）。
  注意：**clip-path 会裁掉外投影**，原来那句 `0 2px 0 rgba(0,0,0,.4)` 一直是死代码，已删。
- 头 `left:6.2 top:0.6 w:9 h:7.2`，切角 clip-path，`inset 0 0 0 1.5px` 主色环。环宽 1.5 而非 2，
  否则 3.2px 高的亮芯被吃掉大半。
- 步枪 `.soldier-rifle`：`left:15.2 top:0.5 w:3 h:10`，深色钢渐变 + `::after` 木质枪托（3×3，底部）。
  只加在 `getDisplayMarkup()` 的 else 分支（基础士兵）里。
- 投影：`13.2×4.4 / left:4.4 / top:17.8 / .30 / border-radius:50%`（中心 y 保持 20，
  跟改前的 17..23 基本同位置，避免整排单位上下跳动）。骑兵共用 `.soldier-shadow`，会一并受影响。
- **坑（已处理）**：8 条 per-unit `.soldier-body { background: var(--color) }` 是 no-op，
  但留着就会把 C1 的暗躯干顶掉，已删除；另外 `.unit.archer/.crossbow/.melee/.firearm/.grenadier`
  的 `.soldier-head` 直接设 background/box-shadow，特异性 (0,3,0) 高于基类，
  必须改成只赋 `--soldier-hi` / `--soldier-core`，否则 C1 在这些兵种上不生效。
- 顺带：`medic-cross` 从 top:6 下移到 top:10（躯干顶边从 y=6 变成 7.4，十字会飘到头部上）。

### 已经排除的误判（避免重复排查）
- `Artillery`（3556 行）与 `RocketLauncher`（3696 行）各自**重写** `getDisplayMarkup()`，
  渲染正常，不是 bug。`RocketSoldier` 在 3940 行把 type 改成 `'antitank'`，复用反坦克兵 markup。

## 沙盘战争：单位图鉴抽屉（commit 736953f）

峰哥提出加图鉴按键展示每个单位的样式、数值与推荐策略。讨论后选定：**侧边抽屉（不遮罩不打断战斗）+ 时代分页签 + 27 句手写战术定位**。

### 结构（复用而非手抄，改平衡自动同步）
- **UNIT_CLASSES 映射**（class Projectile 前）：把原来 6278 与 7068 两处重复的
  type→类 if-else 工厂链合并成一张表，投放工厂与图鉴三处共用。
- **立绘**：图鉴实例化单位类后调 `getDisplayMarkup()` 拿与战场同源的 markup，
  外包 `.codex-unit-scale`，`--fig-scale = 62/unit.getSize()`（统一图标视觉尺寸约 62px）。
  预览元素要 `position:relative` 覆盖 `.unit` 的 absolute 才能居中；hp-bar / ammo 徽章要移除。
- **数值**：从实例字段读 attackPower/attackCooldown/attackRange/minRange/maxSpeed/armorType/damageTable。
  **DPS 必须乘 volleySize**（火箭炮 4 发齐射、蜂巢炮 6 发），否则少算 4~6 倍。
  支援单位（medic/engineer/supply 等）attackPower=0，改读 supportRate/supportRange（HP/s + 半径）。
- **克制条**：damageTable 键为 infantry/vehicle/tank/cavalry，armorType 也是这四个值；
  ≥1.5 标绿（克制）、<0.7 标红（被克）。
- **文案**：`CODEX_TACTICS` 27 句手写定位，是图鉴里唯一会过期的部分，调平衡时要扫一遍。

### 图鉴交互
- 控制栏「图鉴」按钮 → `toggleCodex()`；首次打开才 build（实例化有开销）。
- 四页签：二战16 / 古代陆战5 / 火药4 / 古代水战2（水战单列天然标注"只有赤壁能用"）。
- `GameObject.select()` 里挂了 `focusCodexEntry(this.type)`：**仅当抽屉已打开**才跳转条目，
  不改变平时点选单位的战斗行为。ESC 关闭。
- 页面原本没有 modal/overlay 基础设施，抽屉 z-index 300、fixed 右侧、transition steps(6) 像素风。
