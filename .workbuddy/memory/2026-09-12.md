# 2026-09-12 高斯对比：新增单模型「调正」（每模型独立朝向）

文件 `_pages/splat-compare.html`。峰哥需求：有些模型坐标系不同（如 COLMAP Y-down vs Y-up），
需要**先把各自转到同一角度**再开相机联动比对。选项里峰哥定了：
交互 = **拖动 + 轴向快捷键**；结果 **不按文件名记住**。

## 数学设计
- 每个面板一个 `panel.userQuat`（**世界空间**累积旋转），最终朝向 `R = flip · userQuat`。
  `flip` 放在**左边（世界空间）**，所以点「上下翻转」时所有模型整体一起翻，
  彼此**相对朝向不被打乱**；`userQuat` 在内层承载单模型修正。
- 居中不变式：`world = R·p + t`，模型中心 c 必须落到原点 → `t = -R·c`。
  R 变了 t 必须重算，统一走 `applyGroupTransform`。
- **关键坑：`toUserSpace` 共轭。** 拖动/快捷键给出的都是"世界空间增量 D"，
  但左乘的对象是内层 `userQuat`，必须
  `userQuat ← (flip⁻¹ · D · flip) · userQuat`。
  不换算的话，翻转开启时**水平拖动方向会反**——因为 `flip = Rx(180°)` 只与绕 X 的旋转可交换
  （`f·Ry(a)·f = Ry(-a)`）。轴向快捷键同理。

## 调正交互
- 调正时 `controls.enabled = false`（冻结输入，拖动改为转模型），
  **但仍然参与相机联动**——各面板保持同机位才能边调边和对面比对；
  想换机位就去拖**未调正**的面板画布。
  已核对库内 `OrbitControls.update()` **没有 `enabled` 早退**（L4922 起无判），
  所以 `applyCameraState` 对冻结面板照常生效。
- 模型已居中到原点 ⇒ 绕世界原点转 == 绕模型自身中心转，构图不漂。

## 朝向变化必须强制重排（否则串色）
- 排序用 `splatMesh.matrixWorld`（库 L14102：`mvpMatrix × splatMesh.matrixWorld`），
  而排序可能在 render 之前执行 → `applyGroupTransform` 里补 `g.updateMatrixWorld(true)`，
  否则强排读到的是**上一帧的旧朝向矩阵**。
- `runSplatSort(force, forceSortAll)` 在排序进行中会直接 `return true`（库 L14071，静默丢弃），
  所以记 `panel.sortDirty`，由渲染循环补跑。
  **顺序要对**：`tryResort` 放在 `renderer.render()` **之后**，此时
  `camera.matrixWorld` 与 `splatMesh.matrixWorld` 才都是本帧最新值。
- `tick()` 里 `anyPending = sortDirty || viewer.sortRunning`，有它就不挂起渲染循环，
  防止停在"旧排序结果"上（取代了原来那个只在静止 20 帧后才查排序的嵌套判断）。

## 踩坑：像素基线必须等渲染收敛（差点误判为 bug）
第一轮 E2E 报"重置没回到基线"：nonBg 100249(基线) vs 293961(重置后)，差 3 倍。
**不是朝向问题**：刚 `ready` 时 `splatRenderCount` 还没长到全量，
所谓的"基线"本身就是**残缺渲染**。
修正：ready 后 sleep + 连续强制全排几轮，等 `renderCount == total`（1157662）再取基线。
结果：重置后 nonBg **293979 vs 基线 293959（比值 1.000）**，PNG 差异 **4.61%**，
而真转 90° 是 **34.84%**。
→ **规则：任何像素级断言前，先断言 `splatRenderCount == getSplatCount()`。**
→ 另：滚动校验和**不适合判"有没有变"**（排序顺序微调就会整体翻转），
  要用 PNG 变化像素占比 / 粗格签名。

## 多面板结果（本轮 E2E 覆盖）
- 调正面板 1 时，面板 0 朝向**分毫不动**（单模型独立生效）。
- **调正中面板仍跟随相机联动**（可直接对着另一面板比对调正）。
- 全局翻转后两模型相对夹角 **90.001° → 90.001°**，相对关系未被污染。

# 追加：调正模式加入平移 + 缩放（同一天第二轮）

## 需求
峰哥：调正原来只能转，要加平移和缩放，**控制方式与查看模型一致**。
即左键拖 = 旋转、右键拖 = 平移、滚轮 = 缩放。

## 变换公式扩展
原来只有 R。现在 `R = flip · userQuat`、`S = userScale`（各向同性）、
`t = -R·(c·S) + userOffset`，与 `Matrix4.compose(T,R,S)` 一致。
居中不变式变成 "**缩放后的中心**也要落在原点"：`t = -R·(c·S) + userOffset`。
→ 注意别写成 `-R·c`（漏掉 S），否则缩放后模型会跑出画面。
`applyGroupTransform` 里统一算，任何一项变了都重算全量。

## 拖拽分模式
- `pointerdown` 按 `e.button` 定 `mode`：0→rotate、2→translate、1(中键)→zoom。
- `pointermove` 分发 `rotateModelByDrag` / `translateModelByDrag` / `zoomModelByDrag`。
- 调正时 `contextmenu` 要 `preventDefault()`，否则右键平移会弹菜单。
- `wheel` 监听必须 `{ passive: false }` 才能 `preventDefault()` 掉页面滚动。
- `translateModelByDrag`：像素位移 × `worldPerPixel(panel)` → 世界位移 → `userOffset`。
  `worldPerPixel = 2·tan(fov/2)·distance / canvasHeight`。
- `zoomModelByFactor`：`userScale *= factor`，夹在 `USER_SCALE_MIN=0.05` ~ `MAX=20`。
  **滚轮曲线要抄 OrbitControls**：`zoomDeltaCurve(x)=exp(-x)`、
  `zoomDelta=1.1^dir·0.05`、`factor=1+clamp(z/(exp(z)-1),0.01,1)`、阻尼 0.15/帧。
- 「复原尺寸」按钮：只把 `userScale` 复位成 1，`userQuat` / `userOffset` 保留。

## ⚠️ 重大踩坑：自定义函数名遮蔽 vendor 模块的 `let`（TDZ）
一开始把滚轮曲线写成顶层 `function zf(x)`。
**vendor 模块里有模块级 `let zf`**，内联 `<script type="module">` 与静态导入的
vendor 模块**共享全局词法环境** → 我们的函数进入 TDZ 区 →
`ReferenceError: Cannot access 'zf' before initialization`
→ **整个模块脚本挂掉，轨道旋转/相机联动全部失效**（页面看起来像"点了没反应"）。
- 修法：改名 `zoomDeltaCurve`，并在静态检查器里加防护断言，
  禁止再用短名去撞 vendor 的顶层绑定。
- 教训：**内联 module script 里定义顶层标识符前，先 grep vendor 有没有同名 `let/const/class`。**

## 验证
- 静态 `.workbuddy/tmp/check_splat_compare.js`：**34 项**（新增滚轮曲线命名防护）。
- 数学 `.workbuddy/tmp/adjust_math_harness.mjs`：**23 项**，新增 `groupPosS`（缩放+偏移下的
  居中不变式）、缩放不变式、`matrixWorld` 即时性。
- E2E `.workbuddy/tmp/e2e_adjust_cdp.js`：截图证实滚轮放大（userScale 1→1.60032、
  非背景像素 293959→532967）、右键平移明显可见、「复原尺寸」保留朝向。
  其中 3 项失败（竖直拖动 / 右键平移 / 滚轮缩小）经 PNG 比对确认是
  **CDP 事件注入假象**，非应用 bug；测试端待修。

# 追加：调正旋转改为「环绕视角」（同一天第三轮 · 峰哥提的语义修正）

## 需求
峰哥：「调正模式下的旋转和查看模型时的旋转还不一样，调正模式下的旋转会改变相机坐标系
朝向，我觉得这个没有必要，**和查看模型时保持一致**吧，如果有需要后续再加」。
→ 调正期间的旋转/缩放**不再动模型**，完全交给 OrbitControls（左键环绕、滚轮推拉），
只有右键拖 = 平移模型。退出调正时，把「相机从进入机位 A 转到当前机位 B」这段视角差
**一次性固化**进模型朝向，并把相机拉回 A —— 画面定格在你调好的那一帧。

## 核心恒等式
正交视图下：**绕世界轴 a 把模型转 θ ⟺ 相机绕 a 转 −θ**，画面逐像素相同（harness 实测偏差 0.00e0）。
所以整个交互可以退化成"只动相机"，朝向只在退出时提交一次。

## 固化公式（推导 + 数值双向验证，**没有任何 A 的共轭**）
记相机旋转 `rot`（世界→相机），则视图复合 `view = rot⁻¹·R_model`。
要求「提交后从 A 机位看 == 提交前从 B 机位看」：
```
rot(A)⁻¹·R1 = rot(B)⁻¹·R0   ⟹   R1 = rot(A)·rot(B)⁻¹·R0 = R_cam⁻¹·R0
```
**Δworld = R_cam⁻¹**，其中 `R_cam = rot(B)·rot(A)⁻¹`。
- 为什么不需要 `A·()·A⁻¹`：相机旋转本身就是在**世界系**里表达的，"参考系"就是世界系；
  共轭只在把世界增量塞进**内层变量** `userQuat` 时才需要 —— 由 `applyWorldDelta` 统一处理。
- 第一版曾写成 `Δworld = A·R_cam⁻¹·A⁻¹`，harness 直接报 **136° 误差**（凭空造出一个 A 共轭）。
  改回 `R_cam⁻¹` 后精确到 2.41e-6°。

## 内层共轭（`applyWorldDelta`）
`panel.userQuat` 承载 `R = flip·userQuat`，世界增量 D 要**右乘其共轭**：
```js
R0 = flip·userQuat;  userQuat ← userQuat · (R0⁻¹·D·R0)
```
不要"直接右乘一个裸的轴向四元数" —— 只有 D 与当前 R 共轴时才成立，flip 下必错
（第一版自旋就这么错的，harness 报 179°）。

## ⚠️ 本轮最大坑：固化后多补了一次 `Ry(−az)`「自旋」，把定格画面整个转掉了
- 初衷：退出后"重置视角"方位角回到 0，补一次世界空间自旋把模型规整到方位角 0 的姿态。
- 实际：`applyCameraState(panel, inState)` **随后就把相机拉回 A 机位**了，
  此时任何附加转动**不再被相机抵销** → 等价于对最终画面做一次纯旋转。
- 实测证据（`.workbuddy/tmp/freeze_probe.js`）：
  | | 视图矩阵最大逐元素差 | 像素差异 |
  |---|---|---|
  | 有自旋 | **1.35e-01** | **30.32%** / 均值 14.067 |
  | 无自旋 | **2.50e-05** | **4.8%** / 均值 1.211 |
  `model quat` 从 `[0,0.318,0,0.9481]`（Ry 36.6°）= 两倍 az —— 一眼可见是自旋惹的祸。
- **对照组一锤定音**：在**同一机位**下"转开再转回 + 固化"（按定义回到同一视图），
  差异 **4.7% / 均值 1.137**，与去掉自旋后的 4.8% 同量级 ⇒ 残差**纯是排序地板**。
- 结论：**方位角归一化没有必要** —— 全套面板共用同一个 `mainCameraState`，
  各面板朝向信息已完整存在各自的 `userQuat` 里。多这一步是纯粹的负收益。
- 已在静态检查器里加**"禁止自旋"**回归守卫（含 `applyWorldDelta` 在
  `commitAdjustRotation` 内**恰好调用 1 次**的计数断言）。

## 像素级残差的正确认识（重要）
固化把「相机转到 B」换成「模型转到位 + 相机回 A」，**视图矩阵数值等价（差 2.5e-5）**，
但 `splatMesh.matrixWorld` 变了 → 深度排序顺序变 → 半透明叠加次序不同
→ 少量像素**必然**不同。这是等价表示的固有属性，不是 bug。
**判据不能拿"no-op 连拍"当基线**（实测 0%，渲染器是确定性的），
必须用「同机位往返 + 固化」测出**排序地板**再比。

## 交互实现要点
- **不冻结 OrbitControls**（上一轮的 `controls.enabled=false` 已删）。
  改为：进入调正时把 `controls.mouseButtons.RIGHT = null`（让出右键给平移），
  退出时恢复 `THREE.MOUSE.PAN`。左键/中键完全原生 → 与查看模型手感逐位一致。
- `pointerdown` 只接管 `e.button === 2`，并 `stopPropagation()` 防双触发；
  **`wheel` 监听整体删除**（交还 OrbitControls 原生）。
- 进入调正记 `panel.adjustEnterState = computeCameraState(panel)`，退出时作为 A。
- 「固化朝向」按钮 = 显式调用 `commitAdjustRotation`（不退出调正），
  实现在 `__adjust.commit(i)`。
- `translateModelByDrag` 改用**相机基向量**（right/up）投影像素位移，
  模型才真正跟手（原来用世界轴，转到侧向时方向会歪）。

## 调试钩子（`__adjust` 重写）
`toggle / orbit / axis / translate / commit / quat / cursor / reset`，
新增 `restoreCamera(state)`（仅调试用：把相机搬到指定机位；重置/固化本身不搬相机）。
`__debugCameras` 只有 `{state,target,pos}`，`restoreCamera` 会自己反推球坐标，
所以入参给 `{target,pos}` 即可。**别直接把它塞给 `applyCameraState`** ——
后者要 `target` 是 `THREE.Vector3`，给数组会报 `state.target.clone is not a function`。
