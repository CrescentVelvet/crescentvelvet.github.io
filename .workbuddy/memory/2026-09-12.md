# 2026-09-12 高斯对比：新增单模型「调正」（每模型独立朝向）

文件 `_pages/splat-compare.html`。峰哥需求：有些模型坐标系不同（如 COLMAP Y-down vs Y-up），
需要**先把各自转到同一角度**再开相机联动比对。选项里峰哥定了：
交互 = **拖动 + 轴向快捷键**；结果 **不按文件名记住**。

## 数学设计
- 每个面板一个 `panel.userQuat`（**世界空间**累积旋转），最终朝向 `R = flip · userQuat`。
  `flip` 放在**左边（世界空间）**，所以点「上下翻转」时所有模型整体一起翻，
  彼此**相对朝向不被打乱**；`userQuat` 在内层承载单模型修正。
- 居中不变式：`world = R·p + t`，模型中心 c 必须落到原点 → `t = -R·c`。
  R 变了 t 必须重算，统一走 `applyGroupTransform`。
- **关键坑：`toUserSpace` 共轭。** 拖动/快捷键给出的都是"世界空间增量 D"，
  但左乘的对象是内层 `userQuat`，必须
  `userQuat ← (flip⁻¹ · D · flip) · userQuat`。
  不换算的话，翻转开启时**水平拖动方向会反**——因为 `flip = Rx(180°)` 只与绕 X 的旋转可交换
  （`f·Ry(a)·f = Ry(-a)`）。轴向快捷键同理。

## 调正交互
- 调正时 `controls.enabled = false`（冻结输入，拖动改为转模型），
  **但仍然参与相机联动**——各面板保持同机位才能边调边和对面比对；
  想换机位就去拖**未调正**的面板画布。
  已核对库内 `OrbitControls.update()` **没有 `enabled` 早退**（L4922 起无判），
  所以 `applyCameraState` 对冻结面板照常生效。
- 模型已居中到原点 ⇒ 绕世界原点转 == 绕模型自身中心转，构图不漂。

## 朝向变化必须强制重排（否则串色）
- 排序用 `splatMesh.matrixWorld`（库 L14102：`mvpMatrix × splatMesh.matrixWorld`），
  而排序可能在 render 之前执行 → `applyGroupTransform` 里补 `g.updateMatrixWorld(true)`，
  否则强排读到的是**上一帧的旧朝向矩阵**。
- `runSplatSort(force, forceSortAll)` 在排序进行中会直接 `return true`（库 L14071，静默丢弃），
  所以记 `panel.sortDirty`，由渲染循环补跑。
  **顺序要对**：`tryResort` 放在 `renderer.render()` **之后**，此时
  `camera.matrixWorld` 与 `splatMesh.matrixWorld` 才都是本帧最新值。
- `tick()` 里 `anyPending = sortDirty || viewer.sortRunning`，有它就不挂起渲染循环，
  防止停在"旧排序结果"上（取代了原来那个只在静止 20 帧后才查排序的嵌套判断）。

## 踩坑：像素基线必须等渲染收敛（差点误判为 bug）
第一轮 E2E 报"重置没回到基线"：nonBg 100249(基线) vs 293961(重置后)，差 3 倍。
**不是朝向问题**：刚 `ready` 时 `splatRenderCount` 还没长到全量，
所谓的"基线"本身就是**残缺渲染**。
修正：ready 后 sleep + 连续强制全排几轮，等 `renderCount == total`（1157662）再取基线。
结果：重置后 nonBg **293979 vs 基线 293959（比值 1.000）**，PNG 差异 **4.61%**，
而真转 90° 是 **34.84%**。
→ **规则：任何像素级断言前，先断言 `splatRenderCount == getSplatCount()`。**
→ 另：滚动校验和**不适合判"有没有变"**（排序顺序微调就会整体翻转），
  要用 PNG 变化像素占比 / 粗格签名。

# 追加：调正模式加入平移 + 缩放（同一天第二轮）

## 需求
峰哥：调正原来只能转，要加平移和缩放，**控制方式与查看模型一致**。
即左键拖 = 旋转、右键拖 = 平移、滚轮 = 缩放。

## 变换公式扩展
原来只有 R。现在 `R = flip · userQuat`、`S = userScale`（各向同性）、
`t = -R·(c·S) + userOffset`，与 `Matrix4.compose(T,R,S)` 一致。
居中不变式变成 "**缩放后的中心**也要落在原点"：`t = -R·(c·S) + userOffset`。
→ 注意别写成 `-R·c`（漏掉 S），否则缩放后模型会跑出画面。
`applyGroupTransform` 里统一算，任何一项变了都重算全量。

## 拖拽分模式
- `pointerdown` 按 `e.button` 定 `mode`：0→rotate、2→translate、1(中键)→zoom。
- `pointermove` 分发 `rotateModelByDrag` / `translateModelByDrag` / `zoomModelByDrag`。
- 调正时 `contextmenu` 要 `preventDefault()`，否则右键平移会弹菜单。
- `wheel` 监听必须 `{ passive: false }` 才能 `preventDefault()` 掉页面滚动。
- `translateModelByDrag`：像素位移 × `worldPerPixel(panel)` → 世界位移 → `userOffset`。
  `worldPerPixel = 2·tan(fov/2)·distance / canvasHeight`。
- `zoomModelByFactor`：`userScale *= factor`，夹在 `USER_SCALE_MIN=0.05` ~ `MAX=20`。
  **滚轮曲线要抄 OrbitControls**：`zoomDeltaCurve(x)=exp(-x)`、
  `zoomDelta=1.1^dir·0.05`、`factor=1+clamp(z/(exp(z)-1),0.01,1)`、阻尼 0.15/帧。
- 「复原尺寸」按钮：只把 `userScale` 复位成 1，`userQuat` / `userOffset` 保留。

## ⚠️ 重大踩坑：自定义函数名遮蔽 vendor 模块的 `let`（TDZ）
一开始把滚轮曲线写成顶层 `function zf(x)`。
**vendor 模块里有模块级 `let zf`**，内联 `<script type="module">` 与静态导入的
vendor 模块**共享全局词法环境** → 我们的函数进入 TDZ 区 →
`ReferenceError: Cannot access 'zf' before initialization`
→ **整个模块脚本挂掉，轨道旋转/相机联动全部失效**（页面看起来像"点了没反应"）。
- 修法：改名 `zoomDeltaCurve`，并在静态检查器里加防护断言，
  禁止再用短名去撞 vendor 的顶层绑定。
- 教训：**内联 module script 里定义顶层标识符前，先 grep vendor 有没有同名 `let/const/class`。**

## 验证
- 静态 `.workbuddy/tmp/check_splat_compare.js`：**34 项**（新增滚轮曲线命名防护）。
- 数学 `.workbuddy/tmp/adjust_math_harness.mjs`：**23 项**，新增 `groupPosS`（缩放+偏移下的
  居中不变式）、缩放不变式、`matrixWorld` 即时性。
- E2E `.workbuddy/tmp/e2e_adjust_cdp.js`：截图证实滚轮放大（userScale 1→1.60032、
  非背景像素 293959→532967）、右键平移明显可见、「复原尺寸」保留朝向。
  其中 3 项失败（竖直拖动 / 右键平移 / 滚轮缩小）经 PNG 比对确认是
  **CDP 事件注入假象**，非应用 bug；测试端待修。

# 追加：调正旋转改为「环绕视角」（同一天第三轮 · 峰哥提的语义修正）

## 需求
峰哥：「调正模式下的旋转和查看模型时的旋转还不一样，调正模式下的旋转会改变相机坐标系
朝向，我觉得这个没有必要，**和查看模型时保持一致**吧，如果有需要后续再加」。
→ 调正期间的旋转/缩放**不再动模型**，完全交给 OrbitControls（左键环绕、滚轮推拉），
只有右键拖 = 平移模型。退出调正时，把「相机从进入机位 A 转到当前机位 B」这段视角差
**一次性固化**进模型朝向，并把相机拉回 A —— 画面定格在你调好的那一帧。

## 核心恒等式
正交视图下：**绕世界轴 a 把模型转 θ ⟺ 相机绕 a 转 −θ**，画面逐像素相同（harness 实测偏差 0.00e0）。
所以整个交互可以退化成"只动相机"，朝向只在退出时提交一次。

## 固化公式（推导 + 数值双向验证，**没有任何 A 的共轭**）
记相机旋转 `rot`（世界→相机），则视图复合 `view = rot⁻¹·R_model`。
要求「提交后从 A 机位看 == 提交前从 B 机位看」：
```
rot(A)⁻¹·R1 = rot(B)⁻¹·R0   ⟹   R1 = rot(A)·rot(B)⁻¹·R0 = R_cam⁻¹·R0
```
**Δworld = R_cam⁻¹**，其中 `R_cam = rot(B)·rot(A)⁻¹`。
- 为什么不需要 `A·()·A⁻¹`：相机旋转本身就是在**世界系**里表达的，"参考系"就是世界系；
  共轭只在把世界增量塞进**内层变量** `userQuat` 时才需要 —— 由 `applyWorldDelta` 统一处理。
- 第一版曾写成 `Δworld = A·R_cam⁻¹·A⁻¹`，harness 直接报 **136° 误差**（凭空造出一个 A 共轭）。
  改回 `R_cam⁻¹` 后精确到 2.41e-6°。

## 内层共轭（`applyWorldDelta`）
`panel.userQuat` 承载 `R = flip·userQuat`，世界增量 D 要**右乘其共轭**：
```js
R0 = flip·userQuat;  userQuat ← userQuat · (R0⁻¹·D·R0)
```
不要"直接右乘一个裸的轴向四元数" —— 只有 D 与当前 R 共轴时才成立，flip 下必错
（第一版自旋就这么错的，harness 报 179°）。

## ⚠️ 本轮最大坑：固化后多补了一次 `Ry(−az)`「自旋」，把定格画面整个转掉了
- 初衷：退出后"重置视角"方位角回到 0，补一次世界空间自旋把模型规整到方位角 0 的姿态。
- 实际：`applyCameraState(panel, inState)` **随后就把相机拉回 A 机位**了，
  此时任何附加转动**不再被相机抵销** → 等价于对最终画面做一次纯旋转。
- 实测证据（`.workbuddy/tmp/freeze_probe.js`）：
  | | 视图矩阵最大逐元素差 | 像素差异 |
  |---|---|---|
  | 有自旋 | **1.35e-01** | **30.32%** / 均值 14.067 |
  | 无自旋 | **2.50e-05** | **4.8%** / 均值 1.211 |
  `model quat` 从 `[0,0.318,0,0.9481]`（Ry 36.6°）= 两倍 az —— 一眼可见是自旋惹的祸。
- **对照组一锤定音**：在**同一机位**下"转开再转回 + 固化"（按定义回到同一视图），
  差异 **4.7% / 均值 1.137**，与去掉自旋后的 4.8% 同量级 ⇒ 残差**纯是排序地板**。
- 结论：**方位角归一化没有必要** —— 全套面板共用同一个 `mainCameraState`，
  各面板朝向信息已完整存在各自的 `userQuat` 里。多这一步是纯粹的负收益。
- 已在静态检查器里加**"禁止自旋"**回归守卫（含 `applyWorldDelta` 在
  `commitAdjustRotation` 内**恰好调用 1 次**的计数断言）。

## 像素级残差的正确认识（重要）
固化把「相机转到 B」换成「模型转到位 + 相机回 A」，**视图矩阵数值等价（差 2.5e-5）**，
但 `splatMesh.matrixWorld` 变了 → 深度排序顺序变 → 半透明叠加次序不同
→ 少量像素**必然**不同。这是等价表示的固有属性，不是 bug。
**判据不能拿"no-op 连拍"当基线**（实测 0%，渲染器是确定性的），
必须用「同机位往返 + 固化」测出**排序地板**再比。

## 交互实现要点
- **不冻结 OrbitControls**（上一轮的 `controls.enabled=false` 已删）。
  改为：进入调正时把 `controls.mouseButtons.RIGHT = null`（让出右键给平移），
  退出时恢复 `THREE.MOUSE.PAN`。左键/中键完全原生 → 与查看模型手感逐位一致。
- `pointerdown` 只接管 `e.button === 2`，并 `stopPropagation()` 防双触发；
  **`wheel` 监听整体删除**（交还 OrbitControls 原生）。
- 进入调正记 `panel.adjustEnterState = computeCameraState(panel)`，退出时作为 A。
- 「固化朝向」按钮 = 显式调用 `commitAdjustRotation`（不退出调正），
  实现在 `__adjust.commit(i)`。
- `translateModelByDrag` 改用**相机基向量**（right/up）投影像素位移，
  模型才真正跟手（原来用世界轴，转到侧向时方向会歪）。

## 调试钩子（`__adjust` 重写）
`toggle / orbit / axis / translate / commit / quat / cursor / reset`，
新增 `restoreCamera(state)`（仅调试用：把相机搬到指定机位；重置/固化本身不搬相机）。
`__debugCameras` 只有 `{state,target,pos}`，`restoreCamera` 会自己反推球坐标，
所以入参给 `{target,pos}` 即可。**别直接把它塞给 `applyCameraState`** ——
后者要 `target` 是 `THREE.Vector3`，给数组会报 `state.target.clone is not a function`。

# 追加：调正回归「隔离单模型」+ 退出折算进相机（同一天第四轮 · 峰哥报 bug）

## 峰哥报的 bug（第三轮引入的回归）
「按调正按键时，**鼠标左键会让所有模型一起旋转**，中键会让所有模型一起缩放，
右键只移动当前模型。**退出调正时，所有模型的缩放与视角都会变化**。」→ 与设计初衷不符。

峰哥澄清本意：**调正只控制当前这一个模型的旋转平移缩放**；
控制方式与查看模型一致（可共用函数）；**退出调正后把控制加到相机修正里**；
并且明确 **不要联动（各面板独立机位）**。

## 根因（第三轮的 4f412dd）
第三轮删掉了 `controls.enabled=false` 冻结，改用原生 OrbitControls 环绕 →
调正面板自己发 `change` 事件 → `broadcastCameraState` → **所有面板一起动**。
另外 `commitAdjustRotation` 还调了 `applyCameraState(panel, inState)` + 写
`mainCameraState`，退出时污染全局相机。这就是"退出后所有模型缩放与视角都变"。

## 第四轮方案（峰哥最终拍板）
数学上查清了一个硬约束，直接决定了方案：

**渲染循环每帧 `controls.update()` 末行是 `camera.lookAt(scope.target)`（库 L5018），
且 `camera.up=(0,1,0)` ⇒ 相机横滚恒为 0、无法自由设定。**
把模型上的旋转折算进相机，要求相机转 `R⁻¹`；只有**绕世界 Y 的旋转**折算后横滚仍为 0：

| 模型旋转 | 折算后相机 roll | 用 lookAt 重建的偏差 |
|---|---|---|
| 纯 **Y** yaw | **0.000°** | **0.000°** ← 精确 |
| 纯 X pitch | 10.5° | 12.0° |
| Y+X 组合 | 5.1° | 6.0° |
| 纯 Z | 14.0° | 14.0° |

→ 峰哥拍板：「调正的目的是修改多个模型的旋转差异……**如果 XZ 旋转有问题那就只改 Y 轴吧**」。

**最终语义：**
- 调正中 `controls.enabled = false`（本面板相机完全冻结）+ `pointerdown` 按 `e.button`
  分派三种**模型**操作：左键水平拖 = 绕世界 Y 转模型；中键/滚轮 = 缩放模型；右键 = 平移模型。
- **只提供 Y 轴旋转**（X/Z 的 ±90° 按钮与图纸俯仰全部删除）。
- 退出调正 ⇒ `commitAdjustToCamera`：把 `R_y / S / T` 精确折算进**本面板**相机，
  模型回到纯单位变换。
  - `C' = R_y⁻¹·C`（R⁻¹，不是 R）
  - `eye' = (eye − T)·R_y⁻¹ / S`
  - `panel.suppressBroadcast = true`（try/finally）包住整段，`change` 处理器加
    `if (panel.adjusting || panel.suppressBroadcast) return;` —— **其他面板纹丝不动**。

## ⚠️ 踩坑 1：`controls.update()` 会用 `lookAt` 覆盖你刚写的 `camera.quaternion`
先是按"全量折算任意 R"实现，数学 harness 证到 1.76e-10，但 **E2E 像素差 60.5%**。
原因就是上面那条硬约束：`update()` 末行 `lookAt(target)` 把 `C2` 的横滚抹平成 0。
→ **教训：这个页面里任何对 `camera.quaternion` 的直接写入都是临时的，
  每帧都会被 `controls.update()` 用 `pos + target + up` 重算。**
  （`applyCameraState` 能生效只是因为写的是 pos+target 这套参数。）

## ⚠️ 踩坑 2：yaw 提取的 `atan2` 差 180°
`splitYaw` 里按 `-Z` 前向的水平分量取方位角。three.js 绕 Y 转 θ 把 `(0,0,-1)` 映到
`(-sinθ, 0, -cosθ)` ⇒ **`θ = atan2(-hx, -hz)`**。
写成 `atan2(hx, hz)` 会差 180°（实测 yaw 算成 -140° 而非 +40°，tilt 变成 165° 的怪东西）。
（`splitYaw` 后来因"只改 Y 轴"而整体删除，这条作为数学备忘保留。）

# 追加：退出调正后「其他模型变化视角」（同一天第五轮 · 峰哥再报）

## 峰哥报的现象（原话）
「退出调正模式时，该模型立刻变化视角，然后**转动全体模型时，该模型之外的其他模型
立刻变化视角**。」追问后补充：「退出调正模式后，多个模型都会闪一下变化视角。」

## 排查过程（走了两条弯路，都靠探针否掉）
1. **先怀疑阻尼拖尾**：以为退出时 `controls.update()` 会把未耗尽的
   `sphericalDelta * dampingFactor` 再加一次，逐帧衰减成"飘一下"。
   改写成"临时关阻尼跑一次 update() 清残量"——但**对照实验证伪**：
   旧写法在同一时序下也测不出漂移。改动无害，保留（静态检查器已加守卫）。
2. **再怀疑折算本身让被调正面板闪**：`adjust_freeze.js` 测出像素差 4.72%，
   但 `eye_predict.mjs` 证明相机位置差 1.1e-4、朝向差 0.0039° —— **几何完全等价**，
   4.72% 是 splat 深度排序的固有残差。用 `Page.captureScreenshot` 裁旁观看板区域连拍，
   退出前后**全部 0%**，彻底排除"其他面板被折算影响"。

## 真正根因：相机联动广播的是**绝对机位**
`broadcastCameraState` 原来把源面板的 `{target, azimuth, elevation, distance}` **整体**
推给其他面板。而**调正折算会把模型上的缩放搬进相机**：
实测面板 0 折算后 `distance` 从 **4.000 → 6.762**，面板 1 仍是 4.000。

→ 之后只要在任意面板转动视角，那个"带 6.762"的面板就把 6.762 广播出去，
  其他面板**瞬间跳到 6.762**（= 峰哥说的"其他模型立刻变化视角"）。
  反过来在面板 1 上转，会把面板 0 折算出的 6.762 **覆盖回 4.000**，
  等于**折算白做**。

对照实验（`.workbuddy/tmp/link_isolation.js`）：
| 策略 | 在面板 1 转视角后，面板 0 的距离 |
|---|---|
| 旧（广播绝对机位） | 6.762 → **4.000**（折算被覆盖）❌ |
| 新（只同步朝向） | 6.762 → **6.762**（独立机位保住了）✅ |

## 修法：联动只同步「朝向」，距离与注视点各自保留
峰哥早就明确过「不要联动（各面板独立机位）」，这正是落地方式。
- 新增 `const PER_PANEL_DISTANCE = true;`（策略开关）。
- 新增 `applyCameraOrientation(panel, azimuth, elevation)`：**保留本面板 `controls.target`
  与 `distance`**，只按传入的方位角/仰角重放相机位置。
- `broadcastCameraState` 改为循环调 `applyCameraOrientation(p, state.azimuth, state.elevation)`，
  **不再写 `mainCameraState`、不传 target/distance**。
- 语义：朝向是"大家看的是同一个世界"的共同量，同步它是对的；
  距离/注视点是每面板的独立机位。

## ⚠️ 探针踩坑：合成 PointerEvent 驱动不了 OrbitControls
第一版 `link_isolation.js` 用 `p0.dispatchEvent(new PointerEvent('pointermove', ...))`
模拟拖动，结果**新旧策略都"通过"**——假绿。
OrbitControls 监听的是 canvas 上的原生事件，合成事件不被采纳。
→ 必须用 **CDP `Input.dispatchMouseEvent`**，并**先断言"确实转起来了"**
  （对比拖拽前后的 `pos`），否则断言不可信。

|---|---|

| `.workbuddy/tmp/adjust_isolation.js` | 25 项全过（无回归） |
| `.workbuddy/tmp/adjust_freeze.js` | 定格 4.72%（均值 2.98），对照 0% |
| `.workbuddy/tmp/exit_flash.js` | 退出后两侧相机 d=0.0000，无漂移 |

# 追加：修正上一轮的过度隔离（同一天第六轮 · 峰哥反馈中键/右键失灵）

## 峰哥报的现象
「为什么现在**中键放大缩小和右键平移都不能同步所有模型了**？是遇到了什么困难吗」

## 根因：第五轮把两类"不同步"混为一谈
- **调正折算**产生的距离差（4.000 → 6.762）是**每面板的私有状态**，**不该**广播 —— 第五轮隔离它是对的。
- **用户主动中键/滚轮缩放、右键平移**是**共同操作**，**本来就该同步** —— 第五轮把这类也一并切断了。

第五轮改成"只同步朝向"（`applyCameraOrientation`）后，
距离与注视点完全不传 ⇒ 中键/右键的跨面板联动整体失灵。

## 正确语义：广播「共同基准机位」，各面板叠加自己的私有偏差
每面板新增两个字段：
```js
distFactor: 1,               // 私有距离倍率
targetDelta: new THREE.Vector3(),  // 私有注视点偏移
```
- 广播（源面板 → 基准）：`distance_base = distance / distFactor`、
  `target_base = target − targetDelta`，朝向（azimuth/elevation）直接传。
- 接收：`distance = base.distance × 本面板.distFactor`、
  `target = base.target + 本面板.targetDelta`。
- 无偏差的面板（`distFactor=1 / targetDelta=0`）**退化成整体同步**
  ⇒ 中键缩放、右键平移的原有联动手感**完全保留**。
- 折算时更新偏差：`distFactor = after.distance / base.distance`、
  `targetDelta = after.target − base.target`（朝向变化同步进基准）。
- 「适应」（`fitAllToFirst`）时清空所有面板偏差（全体回到同一初始机位）。

## 对照实验（`.workbuddy/tmp/link_sync.js`，真实缺陷抓取）
在**带偏差的面板 0**（distFactor 1.69）上执行缩小 `×0.95`：

| 实现 | 面板 0 实际缩放 | 面板 1 实际缩放 |
|---|---|---|
| 旧（广播绝对机位） | **×1.6059**（缩变放，比例错乱）❌ | ×1.6060 |
| 新（扣基准 + 叠加偏差） | **×0.9500** ✅ | ×0.9500 ✅ |

旧实现下"缩小 5%"变成了"放大 60%"——这就是峰哥感受到的"缩放不听话"。

## ⚠️ 探针踩坑：CDP `mouseWheel` 对特定元素不可靠
在面板 0 位置注入 `Input.dispatchMouseEvent({type:'mouseWheel'})` 时**始终 0% 变化**，
即使 `elementFromPoint` 命中 `CANVAS`、`controls.enabled === true`、`adjusting === false`。
（同一探针在面板 1 上却生效，说明是注入时序/命中问题，不是应用 bug。）
→ 改为在 `__adjust` 里加 `dolly(i, factor)` 钩子：直接按 OrbitControls 球坐标语义改
  距离再广播。这是**纯逻辑验证**，比事件注入可靠得多。
→ 教训：验证"联动数学"用状态钩子；验证"输入分派"才用真实事件，两者别混。

## 新增调试钩子

# 追加：折算把「朝向」漏出了面板（同一天第七轮 · 峰哥三报）

## 峰哥报的现象（原话）
「按下调正按键，旋转当前模型，再退出调正模式，**当前模型立刻转了一定角度**，
随后鼠标左键控制所有模型转动，**没调正的模型也立刻转了一定角度**。
我只是想让调正模式单独修改当前模型的私有偏差，然后在所有模型同步查看。」

## 根因：`commitAdjustToCamera` 把折算后的 azimuth/elevation 写进了 `mainCameraState`
`C' = R_y⁻¹·C` 会**改变本面板相机的方位角**（实测转 80px ⇒ az 45.000° → 12.911°，
即 −32.09°）。第六轮为了"朝向是全体共同量"把 `after.azimuth/elevation` 写进基准：

- 本面板自己是对的（相机已经吸收了）。
- **其他面板并不会当场跟转**（无接收方拿不到私有 `targetDelta` 会变得没用，且没必要）。
- 于是**基准（az=12.911°）与其余面板的实际朝向（az=45°）不一致**。
- 下次**任何一个面板**广播（左键一转就广播）→ 本面板被按新基准重放 ⇒ az 12.911° → −11.815°，
  又转了 **24°** —— 这就是"没调正的模型也立刻转了一定角度"。

一句话：**折算不是一个"朝向事件"，它只该改这一个面板的私有偏差。**

## 修法：朝向也纳入「私有偏差」
- 每面板新增 `yawDelta`（相对共同基准的**私有偏航增量**，弧度）。
- 折算时：`panel.yawDelta += normalizeAngle(after.azimuth − base.azimuth)`，
  **绝不写 `mainCameraState.azimuth/elevation`**（基准保持不动）。
- 广播（源 → 基准）：`azimuth_base = normalizeAngle(state.azimuth − sourcePanel.yawDelta)`。
- 接收：`azimuth = base.azimuth + panel.yawDelta`，与 `distFactor` / `targetDelta` 同构。
- 无偏差面板（`yawDelta=0`）退化成整体同步 ⇒ 左键转动的原有联动**完全保留**。
- `fitAllToFirst` / 换模型时清空 `yawDelta`；新增 `normalizeAngle(a)` 做 (−π, π] 归一。
- `__debugCameras` 增加 `yawDelta`（度）。
