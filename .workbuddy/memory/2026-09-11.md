# 追加：导弹车改为「无朝向载具」（只平移不转向）

峰哥反馈"转向时导弹朝下很奇怪"。诊断：坦克炮管是**贴地的细线**，跟着车体转是对的；
但甲板导弹是**立在车上的垂直物体**，车体转到南向时弹头指向地面，语义崩坏。

关键点：**不能只关掉视觉旋转**。这两辆车 `isTracked = true`（继承 Mortar/Tank），
移动前要"原地转向对准"，若视觉不转，这段对准就变成**看不见的停顿**，看起来像车无故卡住。
所以新增一个语义标志 `fixedHeading`（`GameObject` 基类默认 `false`），
在 3 处生效，**保留 `isTracked = true`** 以维持"停车开火、不乱走位"的行为：

| 位置 | 改动 | 作用 |
|---|---|---|
| `updateVisual()` | `--angle` 恒为 `0deg` | 车体+甲板导弹+发射特效全部恒朝上 |
| `moveTowardTarget()` | 跳过 `isTracked` 分支 | 改走自由平移分支，任意方向直接平移 |
| `handleSeparation()` | 跳过轴向推斥投影 | 被友军挤开时可横移，不再只沿（不可见的）车头方向 |

`BallisticMissile` / `CruiseMissile` 构造函数各加 `this.fixedHeading = true;`。
开火链未受影响：两者 `tryAttack` 都不做 `isFacing` 门禁（只有 `turnToward` 设逻辑角，
现在不参与渲染），`holdAndAttack` 的履带分支照旧让它们停车开火。

## 新增验证：`.workbuddy/tmp/heading_harness.js`（37 项断言，可复用）
1. 旗帜位：只有 `ballistic` / `cruise` 为 `fixedHeading`，且 `isTracked` 仍为 true；
2. 全 27 类跑 `updateVisual()`（`angle=137`）：无朝向载具 `--angle` 必须是 `0deg`，其余必须是 `137deg`
   （这条同时防止漏改和误伤）；
3. 侧向移动对照：车头朝上、目标在正右方 → 导弹车 `dx>0`（真的平移），坦克 `dx=0`（仍被对准逻辑拦住）。
