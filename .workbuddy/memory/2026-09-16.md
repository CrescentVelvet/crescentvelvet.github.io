## text_processor 改造定案（commit 5044487）
1. **角色定位**：text_processor 是「生产者」——OCR → 格式化 → 按月拆分加密导出月文件 + manifest.enc。
2. **导出语义 = 整月替换**：输出区 HTML 按 `<p>` 行扫描，日期头开组、组随月键。REVIEW_REF_RE 优先
   （回顾行归当前月）、「撤回了一条消息」行丢弃、日期头之前的行无归属丢弃。已有数据的月份导出前
   `confirm` 警告（整月替换语义，旧内容会被覆盖）。
3. **拆月实现关键决策**：**不用** parseDecryptedText 的条目结果重建（会丢高亮 span 和日期行后缀），
   而是直接 DOMParser 扫 `<p>` 原样切分（保留 outerHTML，高亮/后缀无损）。p 内多行时逐行检测日期头
   （防单 p 混多日期头）。纯撤回 p（仅一行且含撤回词）丢弃。
4. **manifest 联动**：解锁时预载 manifest（失败不阻塞，导出时新建骨架）；逐月 mergeMonthIntoManifest
   → 加密导出 manifest.enc。与 enc_reader 导出完全同口径（同一共享函数）。
5. **加密导入**：需先解锁 DEK（同一把钥匙），FileReader → decryptData → 直接进编辑区。
   `this.value = ''` 重置（同名文件可重复导入）。
6. **文件名**：从 `encrypted_log.txt`（旧流程需手动改名）改为直接 `YYYY-MM.txt`（放回即入库）。
7. **crypto-js 引用全删**（script 引用 + CryptoJS 调用）。全站运行时引用清零，
   只剩 _design/diary_tree_plan.md 历史文档记载（保留不改）。
