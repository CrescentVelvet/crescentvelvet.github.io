## 0. 结论：最大难关不是美术素材

**判断**：美术可生成、可外包、可替换；而且本站既有三个游戏（`tower_defense` 11337 行 /
`sandbox_war_game` 7788 行 / `game_plane` 2727 行）**本来就是零位图素材路线**
（`game_plane` 只用了一张 `images/heart.png`）。美术是「最容易被误判成瓶颈」的那一环。

难度排序（难 → 易）：

| # | 难点 | 为什么 |
|---|---|---|
| 1 | **6 个 boss 各一条专属规则** | 米达斯不能近战（只能扔金雕像）、塔罗斯只砍脚后跟、美杜莎必须背对……**没有一套通用打法**，等于 6 个 mini-game |
| 2 | **手感帧数据** | 无法生成、无法外包；起手/命中/收招、hitstop、击退、无敌帧、输入缓冲只能反复试玩微调 |
| 3 | **z 轴纵深判定** | 两轴对齐（`|Δz| < 阈值`）才是清版动作「打空」的来源，也是它手感的精髓 |
| 4 | **关卡与敌人编排** | 清版动作的乐趣大半来自节奏：成组出现的时机、地形对走位的限制 |
| 5 | 美术素材 | 可生成 / 可程序化 / 可买；本项目直接选零位图 |
| — | 版权 | 不是「难关」是「红线」，见 3.1 |

## 1. 事实底账（可回原文核对）

### 1.1 原版身份与版本差异

- 《双刃战士》= **Nitrome《Double Edged》**。Flash 首发 **2009-06-22**；**HTML5 重制 2024**
  （Nitrome Wiki 记「2024-08-04 最早已知可用」，4399 H5 版页面标 2024-05-07）。麻球游戏亦收录。
  出处：Nitrome Wiki / Nitrome Fandom / 百度百科「双刃战士」条目。
- ⚠️ **Flash 原版 2.5MB，4399 H5 版 19.66MB，体积差 8 倍** ⇒ **H5 版大概率是重新实现，
  手感未必等于 2009 原版**。这条直接影响「手感对齐哪个版本」的决策（见 3.5）。
- 4399 页面明写「**该游戏第 8 关无法过关**」—— 原版已知 bug。复刻时是否保留属设计选择。

### 1.2 关卡结构

- **12 关 = 3 个循环**，每循环固定模板：`普通关 → 半 boss 关 → 普通关 → 硬 boss 关`。
  出处：Nitrome Wiki，原文 "The pattern goes by a normal level, followed by a half boss level,
  followed by another normal level, followed by a hard boss level."
- ⇒ **关卡不是逐关手编的，是套模板的**。这是最值钱的一条结构发现。
- 三阶段场景：1-x 森林空地 / 2-x 古罗马废墟平地 / 3-x 白骨荒野。

### 1.3 操作（含纵深证据）

| 玩家 | 移动 | 攻击 | 跳跃 | 特殊攻击 |
|---|---|---|---|---|
| P1 | **方向键 ↑↓←→** | `,` | `.` | `,`+`.` |
| P2 | **W A S D** | `G` | `H` | `G`+`H`（需能量满） |

**证据链（决定性）**：跳跃是**独立按键**（`.` / `H`），而 ↑↓ 被明确归入「移动」——
百度百科「玩家1: 方向键↑↓←→**控制移动**，键跳跃」；4399 移植版说明「左边**上下左右**按钮操控角色的移动，
右边 A 为攻击，J 为跳跃」；Nitrome Wiki Touchy 版「D-pad **up/down/left/right** - move」。
⇒ **↑↓ 只能是纵深走位**。游戏类型标注亦为 "Side Scrolling, **Beat 'em Up**"。

### 1.4 武器（7 种，全部近战，只有弓是远程）

| 武器 | 特性 |
|---|---|
| 匕首 | 玩家主武器，**不可丢弃**；丢了上一把武器后会**自动回到手上** |
| 剑 | 每关开局武器；近战 |
| 战斧 | 略强于剑，但**不能击晕/击杀**【该措辞出自 Wiki 原文，语义存疑，见第 6 节】 |
| 战锤 | **很强；命中即击晕 + 强制击退到屏幕边缘** |
| 三叉戟 | 蜥蜴人使用 |
| 弓箭 | **唯一远程**，可射穿全屏，伤害高 |
| 狮吼锤 | 似战锤但更强，**仅 3-1 出现** |

规则：**手持同类型武器时无法拾取地上的同类武器**。

### 1.5 敌人的耐久数值（可直接当验收锚点）

| 敌人 | 所需攻击次数 |
|---|---|
| 士兵 | 剑 **2** 下 |
| 指挥官 | **3** 下；**被攻击后进入昏迷（不死）** |
| 角斗士 | 多发；耐久高于士兵，**推荐空中打或从背后打** |
| 蜥蜴人 | 三叉戟或长舌两套攻击；**丢武器后不会捡新武器** |
| 赫卡忒牧师 | **3–5** 下；命中后会**瞬移到屏幕他处**；能复活骷髅、能把你变成鸡（蹲跳可躲法阵） |
| 骷髅 | 剑需**很多下** |

### 1.6 玩家血量与拾取物

- 玩家为**血条制，不是固定挨打次数**（Wiki 未给出精确数值）。
- 羊肉（drumstick）**全回**；火鸡（turkey）**回一半**。金币为分数，可由击败敌人 / 投掷宝箱 / 打半羊人获得。

### 1.7 危险物（只有两种）

| 危险物 | 效果 |
|---|---|
| 尖刺坑（spike pit） | **很小**；接触使玩家**眩晕**（stun），**不是即死** |
| 移动尖刺（moving spike） | 成组升起 |

**无平台、无梯子。** 出处：Nitrome Wiki Hazards 章节。

### 1.8 双人规则（原版事实）

- **存在友伤**：可以打伤队友，队友反击也会受伤 ⇒ 站位本身是设计资源。
- 米达斯 / 美杜莎石化状态下，**可以把队友当武器扔出去**（原版彩蛋；不额外扣队友血）。
- 击败 boss 后两人**必须互斗至只剩一人**，游戏才算真正结束（双人专属结局）。

## 3. 定案规格

### 3.1 口径与版权边界

- **复刻骨与手感，重做皮**；**剧情、世界观、角色全部改为中国传统题材**。
- ⇒ 名称、角色形象、美术、剧情**四项版权风险一次清空**；机制/规则不受版权保护
  （一般认知，非法律意见）。
- ⛔ **「双刃战士」这个中文名与「Double Edged」均不可沿用**；主角不可用斯巴达形象。
- 对外名称**待切片二定世界观时再起**。页面文件名先用 `_pages/dual_blade.html`
  （内部标识，不代表对外名称）。

### 3.2 物理模型（三轴）

```
X  = 左右      —— 主推进轴 / 卷轴方向
Z  = 纵深      —— 走位 · 躲避 · 前后包夹
Y  = 跳跃高度  —— 独立轴，仅用于躲地面 AoE 与空中攻击
无平台、无梯子；危险物 = 尖刺坑（眩晕）+ 移动尖刺
```

三个直接后果（必须落到实现里）：

1. **攻击判定是两轴对齐**：命中条件为 `|Δz| < HIT_Z_TOL`，不是一条线 —— 这是「打空」的来源。
2. **渲染需要 z 深度排序**：同一 z 谁在前谁在后；屏幕 `y = baseline + z * Z_SCALE`。
   绘制顺序 = 地面 → 实体（按 z 升序）→ 前景装饰。
3. **敌人 AI 要用 z 轴包夹**：「敌人从两侧夹击」在纵深游戏里有第三层含义。

**红利**：纵深走位**不增加美术量** —— 角色只做左右两套朝向（镜像），z 移动只改屏幕 y。

### 3.3 技术栈与渲染

- **单文件 HTML + Canvas 2D 手写，零引擎零构建**（沿用本站传统）。
- **Canvas 2D 主体 + DOM 只做 HUD/菜单**。依据：`tower_defense` / `game_plane` 这类实时游戏
  走的是 `getContext('2d')`；`sandbox_war_game` 那套 DOM+CSS 部件拼装能成立，是因为
  **单位数量少、交互以点击为主**。清版动作需每帧全屏重绘（卷轴、受击白闪、hitstop、粒子），
  DOM 方案的样式重算 + 合成开销在几十个实体时就开始掉帧。
- **逻辑固定 60Hz 步长**（accumulator 累积 + 余量截断），**不可用可变 dt** ——
  帧数据本身就是手感的载体，可变步长会让「起手 8 帧」失去意义。渲染不做插值。

### 3.4 内容：每种只做最低覆盖量，但必须数据驱动

**约束**：内容先做一两种，留扩展空间 ⇒ **内容定义与逻辑必须分离**，
行为用**标签组合**描述，否则「留扩展空间」只是句愿望。

| 类别 | 切片一做 | 为什么是它们 | 留到以后 |
|---|---|---|---|
| 武器 | **剑**（开局默认，同时承担「武器丢失后回退」的默认武器角色）+ **战锤**（`stun` + `knockback: toEdge`） | 覆盖「纯伤害」与「伤害 + 状态效果 + 强制位移」两条**完全不同**的代码路径 | 匕首/战斧/三叉戟/弓/狮吼锤。**弓留后**：投射物是独立子系统（生成/飞行/命中/回收） |
| 敌人 | **士兵**（剑 2 下死；直线接近 → 近战）+ **角斗士**（耐久高，**正面难打，背后与空中攻击才有效**） | 士兵验最简 AI；角斗士验「条件性有效」—— 它才是 z 轴与跳跃价值的体现，**原版就是这么设计的** | 指挥官 / 蜥蜴人 / 赫卡忒牧师 / 骷髅。抓取投摔留后（太贵） |
| 危险物 | **尖刺坑**（接触 = 眩晕 N 帧，非即死） | 一层效果，验状态系统 | 移动尖刺（「时序 + 位置」复合机关，属第二层） |
| Boss | **不做** | 见 3.9 的风险顺序 | 切片二**立刻**做米达斯 |

**可选追加（若成本接近零）**：指挥官 —— 它「被打晕不死」复用的就是战锤的
`stun` 状态 + 一个「晕倒后可补刀」的状态机，几乎免费。

⚠️ **投掷物系统（举起宝箱/野猪/金雕像再扔）切片一不做。** 但它在切片二**必须**做
（米达斯的唯一解法就是扔金雕像），所以留到切片二与米达斯一并实现。

### 3.5 手感：靶子、参数、校准方式

- **靶子 = 4399 H5 版**（`h.4399.com/zzy/240856.htm`，无需插件）。接受「它可能偏离
  2009 原版」这个不确定性 —— 手感对齐本质是**相对**目标，参照物一致即可达成一致。
- **不做逐帧实测**。理由：① 数帧是专业拆解工作，投入产出比在本阶段不划算；
  ② 靶子本身可能是虚的（19.66MB vs 2.5MB），为不确定的参照做精密工程不值；
  ③ 「感觉不对」是玩家几秒就能给出的信号。
- **校准循环**：峰哥玩 H5 版 → 给出感知反馈（「攻击太拖」「击退太远」「被打后起不来」）
  → 改参数。**目标从「数值相等」放宽到「观感一致」**。
- **起始参数（⚠️ 全部是品类经验推测值，不是原版实测，可随时推翻）**：

| 参数 | 起始值 | 备注 |
|---|---|---|
| 起手帧（按下 → 判定生效） | 8～10 帧 @60fps（133～167ms） | 只求「一上手就有分量」 |
| 命中停顿 hitstop | 3～5 帧 | 命中方与受击方同时冻结 |
| 击退位移 | ≈ 0.5 倍角色身高 | 战锤为 `toEdge`，例外 |
| 受击后无敌帧 | 0.6～1.0 s | |
| 输入缓冲窗口 | 6～8 帧 | 攻击结束前的预输入 |

- **调试面板（运行时滑块 + 参数回显 + 一键导出现值）推迟到切片二**：
  参数只有七八个时，改常量 + 刷新比拖滑块快；等 boss 特殊规则进来、参数翻几倍时再做。

### 3.6 单人优先 ⇒ 架构预留，表现层不做

**峰哥定：只做单人模式，双人后期再扩展。**

- **数据层预留**：`players = [ createPlayer(INPUT_MAPS[0]) ]` 数组 + 输入映射表，
  **不得**散落 `player.x` 这类全局引用。预留成本 ≈ 0；不预留的代价是加第二人时全量重写。
- **表现层一概不做**：1P/2P 标识、友伤、复活规则、双人互斗结局。
  ⇒ 原版 1.8 的三条双人规则**全部推迟**。

### 3.7 关卡数据格式与 1-1 编排

- **格式 = 手写 spawn 时间轴数组**，不做编辑器：

```js
// 概念形态，非最终代码
[ {at: 0,   type: 'soldier',  from: 'right'},
  {at: 180, type: 'soldier',  from: 'right'},
  {at: 360, type: 'gladiator',from: 'left' }, ... ]
```

- **1-1 编排骨架**（按原版顺序简化，原版 1-1 = 士兵 → 指挥官 → 野猪 → 两侧夹击 →
  角斗士 → 半羊人收尾）：
  1. 开场空地：**2 名士兵**从右侧接近 → 教学：攻击
  2. **3 名士兵**成组（其中若做指挥官，则 1 名）
  3. **1 名角斗士** → 教学：空中打或从背后打（这一关的核心教学点）
  4. 走到关卡右端 → 结束
- 卷轴推进方式：**线性推进**（走到推进线触发下一波），不是「清完才放行」。

### 3.8 美术方向（几何/剪影）

- **几何/剪影皮，零位图素材。**
- 视觉语言（草案，可推翻）：
  - 角色 = **实心剪影 + 一层亮边**（可读性；这条是从 `sandbox_war_game` 的
    「移动物一律暗色轮廓」反向推的）
  - 命中反馈 = 命中瞬间白闪 2 帧 + 受击方 **1.15× 挤压**（squash & stretch）
  - 武器 = 手部挂点的**一组多边形顶点数据** —— 这正是零位图方案最大的红利：
    **角色 × 武器的组合数是「加法」不是「乘法」**，像素方案里它是乘法
- **主角形象提案**：两名持械武者，一红一黑配色，靠**头饰形状**而非颜色区分
  （红绿色盲友好 —— 与 `todo_list.html` 里 dropped 状态用空心虚线而非色相的判断同源）。
  剪影皮的好处：换朝代/门派设定只改顶点数据，不动逻辑。
- **主题材粒度**：只定**气质 + 配色 + 主角形象**；**世界观与 6 个 boss 的机制映射推迟到切片二**。
  理由：**先有能打的系统，再设计能打进去的 boss，反过来一定返工。**

### 3.9 切片边界（明确不做）

| 不做 | 归属 |
|---|---|
| 米达斯及其后所有 boss、boss 层架构 | 切片二（**必须立刻做米达斯** —— 那是最大架构风险，不许拖到切片三） |
| 地图 / 选关界面、对话、公主线、双结局、通关后互斗 | **永久砍掉**（剧情不复刻） |
| 双人模式全部表现层 | 后期扩展 |
| 弓箭及投射物系统、投掷物系统 | 弓 → 扩展；投掷 → 切片二（米达斯依赖它） |
| 老虎坐骑、半羊人、宝箱、野猪、鸡等交互物 | 切片二及以后 |
| 原版「第 8 关无法过关」的 bug | 待定，见第 6 节 |

## 4. 验收清单（切片一）

每条都要求**可脚本化断言**，不写「看起来对」这种条目。

| # | 断言 | 手段 |
|---|---|---|
| 1 | 逻辑步长恒为 60Hz | 探针 `__tick` 计数 ÷ 墙钟时间 = 60 ± 1 |
| 2 | 两轴判定成立 | 构造 `Δz` 略大于 `HIT_Z_TOL` 的一击，断言**必然打空**；略微小于则必中 |
| 3 | 战锤抬到屏边 | 导出击退终点 x，断言 ≥ 屏边 − ε |
| 4 | 眩晕状态生效 | 接触尖刺坑后 N 帧内输入被忽略（断言位置不变） |
| 5 | 武器回退 | 交出当前武器后，默认武器（剑）回到手上 |
| 6 | 数据驱动 | **不改逻辑代码**，仅新增一条武器定义即生效 |
| 7 | 零外部资源 | 断言整个加载过程**无任何图片请求**（零位图） |
| 8 | 单人数组化 | `players.length === 1` 且为数组，玩家输入经 `INPUT_MAPS` |
| 9 | 60fps | 40 个实体同屏无掉帧 |
| 10 | 语法与结构 | `node --check` 通过（若是内联 JS 则抽检）+ CSS 括号平衡 |

⚠️ **本站落地已知三个坑（复用既有记忆，别再踩）**：

1. 页面 front matter 需 `author_profile: false` + `classes: wide`（本站惯例）。
2. **`main.min.js` 的 greedy-nav：`#site-nav` 缺席 ⇒ 每次加载必栈溢出。**

   ⚠️ 该游戏页**不能**用 `--headless --screenshot`（本机实测静默失败）。

## 5. 被否决的方案（连同理由一起留着，别再提）

| 方案 | 否决理由 |
|---|---|
| 1:1 全复刻（含像素素材） | 素材侵权红线明确；且像素帧提取本身是不小的工程 |
| 像素风手工逐帧 / 生成式 sprite sheet | 角色 × 武器的素材量是**乘法**；且生成后仍需「抠图→对帧→定位点」一整套管线 |
| 战斗沙盒（空场专门调手感）先做 | 清版动作的手感**离不开关卡节奏**（成组出现的时机、走位空间的地形限制），空场里调顺的手感进真关卡会变 |
| 第一切片就含米达斯 boss | 基础循环未稳时，手感与 boss 机制的问题会互相掩盖 |
| 先逐帧实测 H5 版数值再实现 | 数帧成本高，且靶子本身可能已偏离原版 |
| 一开始就做运行时调试面板 | 参数只有七八个时，改常量 + 刷新比拖滑块快 |
| 现在定完整世界观与 6 boss 映射 | 会把 boss 机制绑死在既有角色库上；顺序必须是「先有系统，再设计 boss」 |
| 现在写完整 12 关规格 | boss 机制需调顺战斗系统后才能真定，现在写大概率返工 |
| 纵深走位不存在（**我的错误结论**） | 已被一手证据推翻，见第 2 节 |

## 6. 待核实 / 待定（不进规格，需实机确认）

1. **【待核实】** 纵深走位时角色是**保持左右朝向**还是**转向正面（背对镜头）**？
   决定动画套数，直接影响美术量。**峰哥玩 H5 版时看一眼即可。**
2. **【待核实】** 战斧「不能击晕/击杀」—— Wiki 原文措辞可疑，需实机确认是
   「不能击晕」还是「不能秒杀」。
3. **【待核实】** 玩家血条的具体数值（挨几下死），Wiki 未给出。
4. **【待核实】** H5 重制版是否忠实于 2009 原版手感（无外部手段可判断，只能靠玩）。
5. **【待定】** 复刻时是否保留「第 8 关无法过关」这一原版 bug。
6. **【待定】** 游戏对外名称（等到切片二定世界观时起）。
7. **【待定】** 页面是否像 `paper_retrieval.html` 那样**全屏铺满**（而非套站点正文宽度）。
8. **【已实测，非待核实】敌人不会视觉堆叠。** 自然推进 2700 帧、峰值同屏 5 个敌人，
   最小屏幕间距 **75.6px**，重度重叠对（<22px）峰值 **0**（`probe_crowd.js`，×2 次不同输入策略）。
   ⇒ 取证截图 `db_v3_gladiator.png` 右侧那团是**探针人为构造的状态**（传送玩家 + `silenceWaves()`
   + 手工刷角斗士），不代表自然游玩。**教训：判读截图前先确认它的构造前提。**
9. ⚠️ **【待核实·重要】关卡从未被证明「能打通」。**
   断言 16（走到终点并判胜）内部调用了 `forceClearEnemies()` 并静音全部波次
   ⇒ 它只证明**几何可达性 + `goalX` 判定**，**不含战斗**。
   实测：用「贴近才出手、不后退、不用纵深、不跳跃」的粗糙策略，玩家在 **t=1350、
   相机 x=1141（约 47% 进度）** 判负（击倒 3）。该策略远弱于真人，故**不能据此判定难度过高**；
   但它也说明「难度是否合理」目前**零证据** —— 须真人试玩校准（原定流程即如此）。
   若要自动化验证通关，需要一个会走 z 轴规避的策略脚本，或一个显式的无敌调试开关。
10. **【待核实】** `PLAYER_HP = 100` 为本站自定基准值，非实测；敌人单次伤害同。（见 §6.3）
