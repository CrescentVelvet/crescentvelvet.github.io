# 字符演歌编写指南（无官方参考，从零做一首新歌）

> 拿到一首歌，自己做字符演歌。与移植流程的区别：没有 pyz 可对拍，
> 质量标尺从「逐格一致」变成「设计合理 + 可视觉回放」。
> 前提必读 `_design/ascii_mv_design.md`（版面契约/渲染架构/数据格式）——
> 那篇是从官方作品逆向出来的全部「为什么好看」。

---

## 0. 流程总览

```
选歌 → 建 lyrics.js（歌词时间轴）→ 生成 spectrum.js（频谱数据）
→ 按歌曲结构分段、定章节 → 逐段写场景函数
→ ?t= 快照逐帧调校 + 无声 PLAY 整曲回放 → commit
```

建议先把第一版场景写粗、整曲跑通（每段先一个占位氛围），再逐段加密——
**先完整后精细**，不要第一段没写完就不动了。

## 1. 建 lyrics.js（歌词时间轴）

格式：`window.__LYRICS=[{"time":0.1,"en":"…","zh":"…","end":1.74}, …]`

- `time` = 该行开始唱的秒数；`end` = 该行结束（含拖尾/间隙起算）；
  字幕系统按 `time<=t<end` 显示该行，行间空隙自动显示「[ instrumental ]/[ 间奏 ]」。
- 中英双语都填；英文是官方歌词原文，中文是意译（母语读者主读中文，注意
  `drawSubs` 里中文比英文亮一档，这是设计意图不要改）。
- **怎么打时间轴**：把 mp3 拖进任何带波形显示的音频工具（Audacity 免费够用），
  按句听写起点；也可以先用现成 LRC 歌词文件（`.lrc` 就是 `[mm:ss.xx] 文本`，
  写个小脚本转 JSON，再手工修 `end`）。精度 0.05s 级够用，但段间空隙要留真实
  间隙——**没有间隙的歌词时间轴会让 instrumental 分支永远不触发，整曲失去呼吸**。
- 时长 `DUR` 在页面里是常量，记得同步改（含提示文案 03:32 之类）。

## 2. 生成 spectrum.js（频谱数据）

格式：`window.__SPECTRUM={"fps":30,"bands":48,"frames":[[48个0~1浮点], …]}`，
`frames[i]` 是 `i/fps` 秒时刻的 48 频段归一化振幅。

用途有两处：**底部频谱条**（每帧取一帧画 `._:=|` 五档）和 **`pulseAt(t)`**
（前 10 频段均值 = 低频脉冲，驱动心形缩放/beat 类动画）。生成脚本（Python，
装 numpy + scipy 或 librosa）：

```python
# 骨架：读 mp3 → 每 1/30s 窗口 FFT → 48 个对数频段平均 → 归一化 → 写 JS
import numpy as np
sr, fps, bands = 44100, 30, 48
# y = 音频波形（librosa.load 直接吃 mp3）
win = sr // fps
frames = []
for i in range(int(len(y) / win)):
    spec = np.abs(np.fft.rfft(y[i*win:(i+1)*win] * np.hanning(win)))
    edges = np.geomspace(20, sr/2, bands+1).astype(int)   # 对数频段更贴近听感
    band = np.array([spec[edges[j]:edges[j+1]].mean() if edges[j+1]>edges[j] else 0
                     for j in range(bands)])
    frames.append(band)
frames = np.array(frames) / (np.percentile(frames, 98) + 1e-9)   # 98 分位归一防峰值削顶
frames = np.clip(frames, 0, 1)
# 写出 window.__SPECTRUM={...}
```

要点：对数频段、汉宁窗、98 分位归一（否则底鼓一响全屏爆顶）。
**音频文件不入库**，spectrum.js 是编排数据，可以入库。

## 3. 分段与章节（整曲骨架）

按「音乐结构 × 歌词语义」双重切分：

1. **先听音乐结构**：intro / verse1 / pre-chorus / chorus / verse2 / bridge /
   final chorus / outro。副歌复现处视觉语言要呼应但不重复。
2. **再按歌词语义分场景**：官方作品是「一句歌词一个场景函数」（36 个 `lyric_*`），
   一首歌 3 分钟约 30–50 句——但不必逐句，**按情绪节拍合并成 15–25 个场景**
   是工作量与效果的甜点。
3. 定 5 章标题（`01 / CREATION` 风格），写进 `CHAPTERS`。
4. 路由表按时间轴顺序填 `{a, b, f}`，`a` 必须等于前一段的 `b`（无缝衔接），
   最后一段 `b` 给个大数兜底。

## 4. 场景编写要领（官方作品的「好看」公式）

设计规格 §0 的结论：**每一格字符都被分配了角色**。落实到写作纪律：

1. **三层构图**：背景纹理层（滚动 hex/噪点/雨线，低密度）+ 主体层
   （大字/几何/心形等视觉锚点）+ 伴随文字层（状态行、十六进制、伪日志，
   提供「信息量感」）。官方场景几乎都有这三层。
2. **所有随机用 `hash16(seed)` 确定性伪随机**——同一 t 渲染可复现，
   噪点像纹理一样稳定抖动而不是雪花乱炸。种子常量随便选（`x*71+dy*313` 这种），
   选了就不要改。
3. **动画公式库**：`progress = clamp(elapsed/时长)` 推进度；
   `hash16(int(t*N))%100 < 阈值` 做随时间加密的闪烁；
   `sin(t*ω+相位)` 做周期摆动；多阶段用 `stage = t<a?0:t<b?1:2` + 每阶段 `clamp` 局部进度。
4. **色号语义**：7 档 `D,N,B,W,R,G,K`。约定：R=危险/错误/爱，B=强调，
   W=高光/闪现，N=正文，D/G=背景纹理。**颜色即是层级**，全曲保持一致语义。
5. **节奏感来自时间常数**：闪烁 2–8Hz，滚动 10–30 格/s，大字脉冲 2–4Hz。
   低于 1Hz 的动感到位但存在感弱，高于 10Hz 就是噪点。
6. 每个场景结尾加一行「钩子」——下一场景的元素提前 0.5–1s 渗入
   （裂纹、粒子、颜色），转场不生硬。

## 5. 无参考下的验证方法

没有 pyz 对拍，验证降级为三层：

1. **快照点检**：`?t=<秒>` 快照模式逐场景看关键帧（起点/切换点/终点），
   肉眼对齐设计意图。这是主力工具。
2. **整曲回放**：无声 PLAY 从头放到尾，重点看：字幕间隙是否显示
   instrumental、章节名切换时刻、频谱条随鼓点起伏、转场衔接。
3. **渲染回归**：`node_extract.js` 提取网格快照入库（**自己的作品，
   参考帧可以入库**），改场景代码后跑 `diff_generic.py` 防回归劣化——
   这是移植链的复用，只是参考帧变成「自己上一版的好帧」。

## 6. 文件落地清单（多曲架构，2026-10-30 起）

```
assets/data/ascii_mv/<key>/lyrics.js      ← 歌词时间轴（入库）
assets/data/ascii_mv/<key>/spectrum.js    ← 频谱数据（入库）
_pages/ascii_mv.html                      ← 唯一播放器页，?song=<key> 切歌（缺省 world）
```

**单页注册表，不再每歌复制页面**（旧方案「每歌一页」作废：基础设施两首歌完全
相同，复制页面等于修 bug 修两遍）。页面内 `SONGS` 注册表每歌一份配置：
标题/艺人/时长 `dur` 与显示文案 `durTxt`/数据目录 `dir`/chrome 标题 `chrome`/
文件提示 `fileHint`/说明尾句 `noteTail`/`scenes` 路由表/`chapters` 章节表。

新增一首歌 = 三处：

1. `SONGS` 加一项（场景表可先空 = 全程 fallback，字幕/频谱先跑起来）；
2. 场景函数（**独立前缀**，如 `lu_`），函数声明有提升，写在路由表之前即可；
3. `assets/data/ascii_mv/<key>/` 两份数据 + 页头切换器加一个 `<button>`。

歌间隔离约定：`?song=` 只接受注册表内的 key（非法值回退 world）；
切换器点击跳 `?song=`（保留 `t` 等参数）；`DUR`/chrome/章节全部从 `SONG` 读，
**禁止再出现按歌硬编码的全局常量**。回归 E2E 场景 D 覆盖切歌全链路。
