# 日志时间轴 — 美化定案（2026-09-15 设计评审）

> 本文是 `_pages/diary_tree.html` 美化的**定案规格**。所有条目都在
> `_design/tree_mock.html` 里用**同一份确定性合成数据**渲染验证过（未经验证的不写进来）。
> 原始需求见 `diary_tree_plan.md`。

## 0. 评审方法（先说清楚结论是怎么来的）

- 建了一个示意页 `_design/tree_mock.html`，用 `?v=` 在**同一份数据**上切换方案：
  `O`=现状复刻（对照）、`A/B/C`=三种布局方向、`H1/H2/H3`=展开形态、`F`=单月聚焦、`D`=日详情。
- 合成数据：2023(5–12月) / 2024 / 2025 / 2026(1–9月) → **41 月 / 930 天 / 1222 篇 / 155 万字**，确定性种子。
- 用 CDP 直驱系统 Edge 抓图（`.workbuddy/tmp/shot_mock.js`），同视口、同 DPR、同缩放，
  **画面里唯一的变量就是那个设计决定**。带 `~x,y,w,h` 参数可裁切做 1:1 可读性验证。
- `_design/` 不参与 Jekyll 构建（已核实 `_site` 内无产物），所以示意页可以安全留在仓库里。

---

## 1. 现状的病根

**不是"配色不好看"，是「静止视图几乎不承载信息」。** 1440×900 四列时 `fitAllYears` 算出
scale≈1.0，恰好落在 `月表头阈值 0.52` 之上、`日节点阈值 1.08` 之下 ⇒ **默认视图正好是信息最少的一档**：
48 个几乎同色的浅橙卡。卡片的"活跃度"只在 `fillAlpha` 0.72→0.90 之间摆动，肉眼分不出；
底部 3.2px 活动条在 2.4× 下像一条误画的横线；满月金框像 focus ring；
legend 解释的 4 种分类色在默认视图里几乎无处可看；放大后卡片退化成巨大的空盒子。

## 2. 定案规格

### 2.1 卡片：分段堆叠柱（`v=H3`）

一个渲染器同时给出两种读数，**静止 → 放大完全连续，没有形态切换**：

| 通道 | 编码 |
|---|---|
| 柱高 | ∝ 当日字数（**线性标尺**），分母 = `全局单日最大字数 × 0.35`，**全局统一** ⇒ 跨月可比 |
| 柱内分段 | 每段 = 一篇；段色 = 该篇分类；段深 = 该篇字数 |
| ~~背景包络~~ | ~~当月累计字数曲线~~ **已删除**（落地后评审否决，见第 3 节末行） |
| 卡片其它 | 主导分类竖标 · 宋体月序 · `N天 · M篇` · 满月**朱印** · 季节淡彩 |
| 年表头 | 衬线年份大字 + 月数/天数/篇数 + 总字数 + **全年 365 格概览条** |

**截平处理**：超出分母的日子截平，柱体**缩短 1.6px**，上方**浮一条比柱窄 42% 的短线**。
⚠️ 不能用"柱顶深色横线"——实测会被误读成"这一天又多了一篇"，
因为这张图的**柱内分段本身就承载信息**，任何柱顶装饰都必须与"分段"语义显式区分。

**标尺实测取舍**（`window.__scale.table` 导出，非估算）：

| 分母 | 中位日填高（线性） | 中位日填高（√） | 截平比例 |
|---|---|---|---|
| 1701 (0.20×) | 82.8% | 91.0% | 37.1% |
| 2127 (0.25×) | 66.2% | 81.4% | 22.3% |
| 2552 (0.30×) | 55.2% | 74.3% | 17.5% |
| **2977 (0.35×)** | **47.3%** | 68.8% | **13.2%** |
| 3402 (0.40×) | 41.4% | 64.3% | 8.5% |
| 4253 (0.50×) | 33.1% | 57.5% | 5.0% |
| 8506 (1.00×) | 16.6% | 40.7% | 0% |

**关键**：截平比例**只由分母决定，与标尺是否非线性无关**；非线性只改变"填满程度"。
选 **0.35× + 线性**：截平 13.2%（最惨月 2024-12 从 40% 降到 26.7%），
柱高保持成比例（节奏对比比 √ 强 3 倍），留给包络足够的上方空间。

### 2.2 LOD：由 `k = scale / fitAllYears` 驱动

| k | 表现 |
|---|---|
| < 1.30 | 纯色带（无圆角、无间隔、无日号） |
| ≥ 1.30 | 段间出现间隔 + 圆角（"格子感"） |
| ≥ 1.60 | 段内写出日序号 |

**k 只当闸门，底下必须再叠一层「装得下才画」的护栏**（`colW·k ≥ 10px 且 segH·k ≥ 7px`）——
纯 k 闸门会给装不下的短段也写字，密集月必然溢出。
用 k 而不是绝对像素：绝对阈值在"只有两年"或大屏上会在静止态就跳进下一档。

### 2.3 单月聚焦：原位浮层（`v=F`）

单击月份卡 → 卡片**原地浮起、盖住邻居**，**布局一点不变**，背景只压暗 0.38
（压暗太重就看不出"布局不变"，而背景里的柱子正是它在证明这一点）。

浮层内容：题头（年月衬线大字 + 满月朱印）/ 月统计 / **分类构成条 + 图例** /
**左列真月历 7×6**（色深∝字数 + 日号 + 多篇白点）/ **右列当月目录**（分类点 + `8/4 周日` + 字数 + 首句摘要，可滚动）/
底部 `‹ 上月 / 下月 ›`。

⚠️ 浮层是宽的（≈648px），真月历接近正方形 ⇒ **日历只占中间一条，左右大片空白**。
**修法不是调几何，而是把空白改造成内容**（右列目录）。

### 2.4 日详情：单栏长文 + 篇级分节头（`v=D`）

弹窗宽 **560px**（正文列 ≈33 汉字/行，中文舒适区），高度**随内容自适应**。

- 题头：`2024 年 8 月 6 日` 衬线 23px + 周几 + `N 篇 · M 字 · K 段` + 分类圆点
- 分节头：分类色竖条 + `第 n 篇` + 分类名 + 该篇 `字数 · 段数`
- 正文：**宋体 16px / 行高 1.95 / 段首缩进 2 字 / 段距 8px**
- 底部：`‹ 前一天 / 后一天 ›`

**中文折行必须做禁则处理**：`。，、；：！？）】》」` 不允许落在行首 ⇒ 让标点**悬挂在行尾**；
`（【《「` 不允许留在行尾 ⇒ 把前一个字一起挪到下一行。

⚠️ **中文正文字体栈必须给 ≥2 个候选**：`"Songti SC","SimSun",Georgia,serif`。
本机探针实测 `Songti SC` 与通用回退同宽（160.1）⇒ 不存在；只写一个候选会**静默退到通用字体**，
连 A/B 都会看不出差别。探针：`window.__fonts`（量同一串中文在各字体下的宽度）。

### 2.5 视觉基调：`tone=paper`

- **纸纹**：全画布极淡竖向纤维（间距 5px、alpha 0.011~0.015、长度伪随机）。零成本，明显增"纸感"。
- **朱印**：`drawSeal()` 赤陶方章 + 1px 内白边，**替换满月金环**。同时把满月月的统计文字右移 19px 让位。
- 保留季节淡彩。

### 2.6 HUD：从「角落卡片」改成「36px 全宽顶栏」

左＝`日志时间轴` + 一行统计；右＝标尺与 LOD 提示；底部一条发丝线。
同时把布局 `top` 由 78 提到 **96**，为年表头让出完整的 50~94 区间。

⚠️ 这个问题**不能靠挪年份位置解决**——竖排年份也失败（`vcal=1` 留作对照），
因为 HUD 压的正是"列顶"这块地方，年份不管横排竖排都在那里。只能动 HUD 本身。

### 2.7 功能边界

- **(a) 沉浸基础**：键盘（`←/→` 切上下月、`Esc` 逐层退出）、展开动效 150~200ms。
- **(b) 图例变筛选器**：点图例 → 该分类高亮，其余压到 16%（一处钩子覆盖全页所有分类色），
  再加一个 `显示全部` 重置。**零新增 UI 面积换一个真功能**。
  包络线**不跟着变暗**（刻意保留：可以看到"写得多的月份里，有多少是这一类"）。
- **(c) 全文搜索**放二期。数据量不是问题（155 万字在内存里，毫秒级扫描），
  **难的是"命中结果如何映射回 canvas 上的位置"**——搜索→定位→高亮→收起是独立工作量。

## 3. 被否决的方案（连同否决依据，别再走回去）

| 方案 | 结论 | 依据 |
|---|---|---|
| **B 年历墙**（每年 12 个真月历方阵） | 观感最好但**丢掉跨年同月对齐**；格子被高度卡在 ~14.7px、右侧大片空白 | 截图 `tree_B*.png` |
| **C 时光树**（主干+枝+叶） | 信息密度最低、无法精确定位某一天 | 截图 `tree_C.png` |
| **H1 日序矩阵**（31×3） | 被 H3 取代：H1 是"柱子只由篇数决定高度"，丢掉了字数这个连续量 | 截图 `tree_H1_*.png` |
| **H2 放大后换真月历** | **几何上不成立**：卡片是 5.4:1 宽扁形，真月历接近 1:1；2.6× 时方阵只占 ~15% 宽度 | `tree_H2_z2.6.png` |
| **随缩放重排布局** | 对象在缩放中跳动，且必须引入纵向平移 | 交互推演 |
| **√ 标尺** | 截平率与线性**完全相同**（只由分母决定），只是把 300 字日从 10% 抬到 32%，代价是节奏对比被压平 **且把累计包络挤得看不见** | `tree_H3_z1.0_sqrt.png` vs `_lin.png` |
| **居中浮层 / 原地占据式聚焦** | 前者丢空间感；后者要重排 + 纵向平移 | 三选一示意图 |
| **篇级卡片流 / 左日期轴右正文** | 日记是线性阅读，卡片流会让人"扫"而不是"读" | 设计推演 |
| **正文黑体 15px** | 屏幕最稳，但丢掉"日记"气质；宋体 16px 补偿了细笔画 | 1:1 裁切对比 |
| **竖排年份** | 丢掉最强的年份锚点，浅到像装饰，**且没解决 HUD 冲突** | `tree_H3_z1.0_tone=paper_crop350-60-220-140.png` |
| **稿纸横格 / 纯极简去装饰** | 前者与柱状图+包络+刻度叠加成噪声；后者丢掉唯一差异化 | 设计推演 |
| **当月累计包络曲线**（落地后被否决，2026-09-15） | 「前紧后松/月底冲刺」读数的**阅读成本高于价值**——用户看到曲线第一反应是"意义在哪里"；放大档它与日序号、表头文字抢视觉（右端顶到「N天·M篇」与朱印）。已实现后按用户决定删除 | 用户评审真实页面截图 |
| **柱区左侧 30px 月序号列**（落地后被否决，2026-09-15） | 月初低产月份读成一截死空白；月序画在最上层（深色衬线），高柱从下面穿过也压不住它，不需要独占一列。plotL 30→10 | 用户评审真实页面截图 |

## 4. 落地清单与待修项

**待修（示意页与真实页共用）**
1. 真月历行数写死 6 行 ⇒ 5 行的月份（如 2024-08）底部留空，应按 `ceil((firstDow+dim)/7)` 动态定。
2. 浮层右列目录只放得下 6 行（`rows=(calH-26)/38`），31 天的月份被砍太多，需加高浮层或压行高。
3. 缺一个"有空白日"的月份样本（现有选取的是满月，看不到空白态）。

**实现顺序建议**
1. 卡片渲染器（分段堆叠柱 + 包络 + 截平 + 标尺常量）—— 收益最大、风险最低
2. 顶栏 HUD + `top` 调整 —— 顺手修掉历史缺陷
3. LOD（k 闸门 + 护栏）
4. 图例筛选（一处 `rgba()` 钩子）
5. 单月聚焦浮层（含右列目录）
6. 日详情弹窗（含禁则折行与字体栈）
7. 键盘与动效
